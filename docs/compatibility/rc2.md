# 0.1.0-rc.2 兼容范围

本版用于 Mac Apple Silicon 与 Linux x86_64 集中验收。Linux 安装包在 Mac 构建，尚未进行 Linux 实机运行。Mac 包仍未做 Developer ID 签名和公证。

## 历史识别

- 合并本地 `state_*.sqlite`、`thread_history_*.sqlite`、`session_index.jsonl`、普通 `.jsonl` 和 Zstandard `.jsonl.zst` 历史。
- 优先显示原生自定义名称；主对话和后台代理分开，后台记录显示代理身份与父对话。
- 压缩源只读流式解压，不在源目录展开或删除；相同普通/压缩内容合并为一条对话。
- 本地文件大小按磁盘文件字节统计；数据库显示逐对话记录的逻辑字节数，不声称能精确分摊共享 SQLite 页、索引、WAL 和空闲页。
- 2026-11-02 只读调查纠正了“原始文件丢失”的早期判断：实际是旧扫描器漏掉 `.jsonl.zst`。一次完整核对为 24 条主对话、218 条后台记录，真正缺文件 0 条；数量会随 Codex 活动变化。没有删除或重建用户数据库。

## 同步与容量

- 新备份使用 4 MiB 分块、逐块压缩与认证加密、完整性校验和去重。原始 JSONL 内容、图片和工具记录均不剪裁；完整数据库记录单独保存。
- 现有 R2 空间和恢复文件继续使用；可以读 rc.1 的旧备份。参与新备份同步的设备应都安装 rc.2，rc.1 不能读取新分块格式。
- 已验证 1,677,813,136 字节合成历史的完整上传、下载、备份和恢复，SHA-256 相同；峰值 RSS 398,852,096 字节。合成数据高度重复，压缩率不能代表真实图片历史。
- 预览只在本机暂存加密块，读取云端对象清单，不上传历史。预览列出新增加密块、元数据预留及当前空间占用；取消后清理本次暂存，启动时清理中断遗留暂存，不清理备份。
- 默认每次上传上限 500 MiB；原始关联内容或预计上传量超过 100 MiB 时额外勾选确认。后端同时检查预览与实际写入预算。
- 数字仅代表当前同步空间，不是整个 Bucket 的硬配额；其他设备、其他用途、旧版本和中断上传也可能占用空间。软件不自动删除历史版本腾空间。
- 本版清单最大 32 MiB，最多 5,000 份关联对话；单条 JSONL 记录安全解析上限 128 MiB（不是单个文件上限）。极端超限明确阻止，不截断历史。导入前完整备份需要足够本地磁盘空间。

## 原生导入

已验证目标运行时：Desktop `0.166.0-alpha.5.1`、CLI `0.166.0`、VS Code 内核 `0.164.0-alpha.11.1`；保留原 rc.1 的 CLI `0.164.0` 适配。Desktop → CLI / IDE → Desktop 合成往返检查了原历史、早期上下文、图片、工具输出及目标工作目录。

源历史的创建版本是历史元数据，不等同于当前目标运行时版本；新格式不会仅因源记录来自旧版本而拒绝备份。目标可执行文件仍受版本检查，数据库字段或原生验证不兼容时停止并保留恢复备份，不静默丢弃非空字段。

确实只有数据库记录、且普通和压缩原始历史都找不到时，仍完整备份并显示具体原因。原生 Codex 需要原始 rollout，不能凭空重建缺失模型上下文；此类导入在写入前阻止。这不是本次所查两条用户对话的情况。

系统登录、API 凭据、模型/MCP/权限配置不随历史复制。导入前退出占用目标的 Codex；原生检查不发送用户任务。最终在 Mac/Linux 原生界面中的可见性和实际工作验收仍由用户完成。
