# 0.2.0 交付验证

2026-11-03。测试使用独立 Codex 数据目录、独立 Sesshuttle 配置和合成对话。跨机测试使用真正的 macOS ARM64 与虚拟化实验环境中的 Arch Linux x86_64、两个各自运行的 Codex 内核、回环连接上的 S3 兼容测试服务以及可重复响应的本机模型替身。所有写入和续聊留在测试目录。

| 验证 | 结果 |
| --- | --- |
| Mac → Arch → Mac | Mac 从 3 轮历史上传。Arch 导入到原来没有任何对话的 `linux` 项目，核对原生项目分组和对话 ID，用户消息明确交接后续至 5 轮。回传 Mac 并在同一对话续至 7 轮。早期上下文、两端实际工作目录正确，产品注入的环境消息为零。 |
| 各端原生接口 | Mac 的 Desktop `0.166.0-alpha.5.1` 与 CLI `0.166.0` 以及 Arch 的 Linux x64 `0.166.0` 分别完成隔离测试。经 `thread/metadata/update` 指定空项目后，用独立的 `thread/read` 和按项目过滤的 `thread/list` 读回。 |
| 缺图、压缩与项目 | 压缩源记录缺少一张图片时，未确认会阻止导入。确认后在目标副本生成缺图说明。文字、早期上下文、工具记录及正确工作目录保留，续写后返回来源设备仍可接续。原文件的指纹在回传前保持相同。额外的修复测试覆盖选择替代图片和过时的确认。 |
| Linux 桌面进程检测 | Arch 中运行实际 Codex app-server，在模拟 `…/usr/lib/chatgpt/ChatGPT` 启动链下通过内核可执行文件和打开的 SQLite 文件识别目标。另测多个实例及历史目录冲突。这里没有运行用户安装的 GPT 客户端。 |
| Arch 凭据 | 在测试用图形会话和解锁的 GNOME Keyring 中，让 Electron 选择 `basic_text`，验证 Sesshuttle 通过 Secret Service 写入合成凭据，再用新的进程读回。隔离界面也走过“已连接但仅本次保存”后的查看云端和继续原任务流程。 |
| Mac 桌面交互 | 用测试窗口从未连接开始，点标题上传、返回原任务、逐图确认、查看云端，再把同一条对话导入两个目标并核对各自结果。对安装包另行核对入口、环境检测及选中范围。勾选 3 条再筛选至 CLI，能查看另 2 条已选标题。使用同一包内界面在 860 × 650 窗口核对可操作的多选栏、路径用途说明和键盘切换中英文。 |
| 代码及保护 | 36 项核心检查通过，包括分歧版本、过期预览、容量限制、只读压缩扫描、目标部分成功、中断恢复、可恢复删除和共享附件保护。类型检查及 468 条双语界面消息检查通过。 |
| 安装包 | Mac DMG 镜像和归档校验通过，启动隔离窗口。Arch 以普通用户从最终 tar.gz 解压启动，通过渲染界面到主进程的首次扫描。Debian 包的 `amd64` 字段和程序归档与 tar.gz 一致。核对两平台主程序、预加载、界面 JS/CSS/HTML、四个字体和许可文件，校验值见本地 `release/SHA256SUMS.txt`。 |

**仍由用户完成的验收**　此前用户已经确认自己的 R2 已连通，Linux 能看到一条云端对话。本轮没有接入这份真实存储，也没有向用户的 Codex 目录写入测试数据。在用户实际安装的 GPT Linux 客户端中查看侧栏并与真实模型续聊，以及该桌面环境的自动打开方式，留给最终验收。Debian 和各种桌面环境的每种组合没有分别运行。

本轮另对先前讨论的 `Master build_ask` 和 `deploy_ask` 做了只读定位。检查时，两条原生索引所指的位置都有普通 `.jsonl` 文件。先前曾在压缩源中找到 `deploy_ask`。两次检查只描述各自时点，未重建索引或删除数据。
