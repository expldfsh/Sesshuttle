# 0.7.1 本机验证记录

0.7.1 修复 0.7.0 验收中复现的两类界面问题：任务未能开始时没有任何反馈，以及本机回收站恢复后列表仍显示旧状态。同步格式（bundle format 2）、加密、云端布局和主进程的安全校验都没有改变。所有开发期测试只使用临时目录中的合成数据、仅监听回环地址的模拟 S3 和本机应答服务；没有读取或写入真实 `~/.codex`、真实项目或真实 R2。

## 问题与修法

**任务未能开始时没有反馈。** 确认上传、导入或删除时，如果主进程以 `stale_plan` 等错误拒绝，界面会关闭弹窗、清除任务，并把错误写到一个不存在的位置（`place = 'task'`），用户看不到任何提示。

- 任务类失败不再放在单一的提示中，而是保存在任务进度存储里，直到用户关闭、使用恢复按钮，或开始新的同类任务。
- 顶栏任务指示器显示红色失败状态，例如「上传未开始」。任务浮层写明原因、没有上传或导入任何内容，并提供恢复按钮。
- 「刷新并重新预览」会刷新列表，用原来的请求和选项重新打开弹窗，逐步检查后停在新生成的检查清单，或停在第一个需要用户处理的步骤。
- 删除未能开始时写明没有删除或恢复任何内容，并提供「重新查看删除清单」。
- 打开原生应用失败时，错误显示在该应用行下方或任务浮层中，并说明应用没有打开。
- 任何错误所在的位置不在屏幕上时，改在页面顶部显示。
- core 核实了拒绝路径：`engine.execute` 和 `removals.execute` 被拒绝时只执行过只读检查。任务开始后仍然抛出的错误会标记 `started`，界面据此改为说明「可能已处理部分条目」。

**本机回收站恢复后仍显示旧状态。** 「备份与恢复」只在打开时读取一次本机记录，删除弹窗完成后没有通知它。

- 每次会改变本机已保存状态的用户操作结束后（无论成功、失败还是中途停止），App 都会发出信号。页面据此重新读取本机已保存的状态，不扫描本机历史，也不查询云端。
- 已经显示过的云端回收站列表只会标记为「可能已过期」。刷新前，列表中的操作按钮不可用。

## 排查出的同类问题

| 位置 | 问题 | 处理 |
| --- | --- | --- |
| 所有错误提示 | Electron 45（Chromium 156）中 `scrollIntoView` 返回 Promise，`ErrorNotice` 把它作为 effect 的清理函数返回，任何错误提示关闭或被替换时整个窗口变成空白 | effect 不再返回值；复现脚本把渲染进程异常记为失败 |
| 本机应用与项目 | 从任务浮层打开导入弹窗并完成快速验证后，下层页面的应用状态不更新 | 按信号重新读取应用状态和文件夹状态；快速验证失败后同样刷新 |
| 侧边栏角标 | 手动备份的创建、恢复、删除，保留单个副本，以及失败或中途停止的传输和删除之后不更新 | 统一在操作结束后重新读取 |
| 设置 | 授权恢复连接、保存凭据失败后，连接状态不更新 | 所有结果都重新读取 |
| 设置、本机应用与项目 | 重新读取已保存状态时，会覆盖尚未保存的修改 | 有未保存修改时保留正在编辑的内容 |
| 云端回收站 | 「完成已确认的云端清理」后会自动重新读取云端；页首在 780px 宽度下挤成窄列 | 改为标记可能已过期；页首改为换行排列 |
| 同步记录 | 传输或删除结束后的新记录和「需处理」数量 | 修复前已能立即出现，没有发现问题；清除记录失败后也重新读取 |
