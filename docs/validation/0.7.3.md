# 0.7.3 本机验证记录

0.7.3 让永远无法继续、也无法清除的删除任务能被看懂并处理掉。删除本身的安全校验、同步格式和云端布局都没有改变。所有开发期测试只使用临时目录中的合成数据、仅监听回环地址的模拟 S3 和本机应答服务；没有读取或写入真实 `~/.codex`、真实项目、真实 R2 或本机 Sesshuttle 的应用数据。

## 问题与修法

用户的「同步记录」里有一条 2026-11-03 的本机彻底删除任务，显示「删除未开始」，怎么点都报同样的错，也删不掉。原因有三个：

- **无法清除**：`clearActivity` 只接受 `completed` 的删除记录，没开始的和已被新清单替换的记录永远留着，原因只写在鼠标悬停提示里。
- **死循环**：「重新查看删除清单」不先刷新列表，`preview()` 又要求对话全部在 `engine.rows` 中，否则报 `stale_plan`。对话已不在本机时，重试多少次都一样。
- **没有出路**：未开始的删除任务没有放弃入口。

修法：

- `core/activity.mjs` 新增 `removalClearance`，`clearActivity`、`clearableActivity` 和新的放弃操作都用它判断。
- 新增互斥 IPC `discardRemovalJob` 和只读 IPC `checkRemovalClearance`。可清除且未完成的任务卡片显示「放弃此删除任务」，先用确认弹窗说明情况。不可清除的记录在勾选框旁直接显示原因和入口。
- 「重新查看删除清单」先只刷新本机列表，`revise()` 按任务自己的 Codex 数据目录扫描磁盘判断对话是否还在。找不到时报 `removal_targets_missing` 并列出标题，全部找不到时主按钮是放弃，部分找不到时可以「只为仍在的 N 条重新生成清单」。

## 可清除规则

| 情况 | 结果 |
| --- | --- |
| 正在运行（`activeId` 就是这条记录） | 不可清除：`removal_running` |
| `completed`、`replaced` | 可清除 |
| 任何一侧都没有开始 | 可清除，说明「没有改动任何内容」 |
| 已开始，本机回收站副本不存在或为 `restored` | 本机侧已收尾 |
| 已开始，副本为 `removed`，模式是移入回收站或恢复 | 本机侧已收尾 |
| 已开始，副本为 `removed`，模式是彻底删除 | 不可清除：`removal_local_unfinished` |
| 已开始，副本为 `staging`/`prepared`/`removing`/`restoring`/`needs_recovery`/`purging` 或未知状态 | 不可清除：`removal_local_unfinished`，入口是「备份与恢复」 |
| 云端侧未开始或已 `done` | 云端侧已收尾，不读取云端 |
| 云端侧已开始未完成，空间标记没有以这条记录为 `pending` 的事务 | 云端侧已收尾 |
| 空间标记有以这条记录为 `pending` 的事务 | 不可清除：`removal_cloud_pending`，入口是「备份与恢复」 |
| 未连接、连接的是另一个空间、记录没有空间信息或读取失败 | 不可清除：`removal_cloud_unconfirmed`，入口是「连接存储」 |

判断「已开始」时，除 `started` 外，`running`/`done`/`cleanup`/`localCleanup` 状态和 `erasing` 也算已开始，防止缺字段的旧记录被当成什么都没改。空间标记只在用户点击清除或放弃时读取一次，打开页面不读取。列表中需要云端确认的记录先允许勾选，点击时再确认。

## 同类排查

| 位置 | 发现 | 处理 |
| --- | --- | --- |
| 传输记录 `running` | 启动时已由 `recoverLocalState` 改为 `interrupted`，不会一直卡住 | 无需修改，新增重启后的回归检查 |
| 删除记录 `interrupted`/`partial`/`attention`/`replaced` | 只有 `completed` 能清除 | 按新规则判断，不可清除时就地说明 |
| 「清空记录」 | 跳过的记录没有说明 | Toast 写明清除数和需要先处理的数量 |
| 传输的「刷新并重新预览」 | 对话部分消失时报 `invalid_selection`，全部消失时是打不开下一步的空弹窗 | 列出标题，只处理仍在的对话，全部消失时说明原因 |
| 「修复并重试」 | 本次启动还没读过列表时打开空弹窗 | 点击后先读取列表 |
| 「检查副本」 | 没有重复副本时弹窗是空的 | 说明情况 |
| 确认执行时对话已消失 | 记录 `invalid_selection`，界面只给必然失败的重试 | 改报 `stale_plan`，给出「重新查看删除清单」 |
| 未开始的删除重新打开（没有记录的情况） | 弹窗里「刷新并重试」不刷新，一直 `stale_plan` | 先刷新本机列表，缺失时在弹窗里说明并可只处理仍在的对话 |
| 没有清单的旧记录 | 只能得到 `stale_plan` | 新错误码 `removal_plan_missing`，修复动作是放弃 |

## 用户验收

2026-11-08 用户验收通过，包括处理本机 2026-11-03 那条无法继续的删除任务。验收项目如下：

1. **处理 2026-11-03 的删除任务**：升级后打开「同步记录」，找到这条任务，点「重新查看删除清单」，确认提示列出「Find agent work history sync tools」「整理 Week 1 OS 笔记到 Google Docs」两条对话已不在本机。点「放弃此删除任务」，确认弹窗说明「这条任务没有改动任何内容」和「放弃后不会删除任何对话」，确认后这条记录消失，「需处理」数字减少。
2. **对话仍在时不受影响**：另选一条测试对话发起删除，确认正常的预览和执行没有变化。
3. **有待收尾工作的记录**：如果你有部分完成的删除任务，确认勾选框不可用，旁边显示原因和入口，「清空记录」后 Toast 说明有几条需要先处理。
4. **Linux**：在 Arch 上启动 tar.gz，在 Debian / Ubuntu 上安装 `.deb` 并启动一次。
