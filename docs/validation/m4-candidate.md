## 安全与恢复要点

导入检查来源与目标版本、目标进程、资源完整性、预览快照；写入前保存历史和相关索引文件，任务先落恢复日志。失败不假装成功，后续写入被恢复要求拦住。恢复前再保存当前状态，新数据移入受管恢复目录并保留安全备份。

原生验证先只读获取有效配置，再显式禁用所有已配置 MCP、启动钩子、插件和遥测；只恢复并读取历史，不发送任务。Mac 验证进程另外限制网络和写入目录。

正常导入不删除或重建已有数据库；只让目标原生内核识别完整历史。恢复会还原指定备份的历史和索引，因此恢复界面明确说明整个目录的时间点与安全副本。

仅打包本地界面，渲染器无 Node 权限，调用范围有限，显示历史为文本。系统秘密不可保护时不明文保存。远端对象加密，云端版本先写入并校验，再通过条件写入发布指针。没有按修改时间覆盖分歧，也没有自动删除旧云端版本。

## 复验入口

```sh
npm run check
npm test
node scripts/integration.mjs <合成 rollout 文件> <已验证的 Codex 可执行文件>
node scripts/roundtrip.mjs <源端 Codex 可执行文件> <目标端 Codex 可执行文件>
node scripts/native-config.mjs <合成 rollout 文件> <已验证的 Codex 可执行文件>
```

`roundtrip.mjs` 自动创建专用临时实验目录和本机响应服务，仅在 Mac 的进程隔离下执行。界面测试使用 `scripts/ui-fixture.mjs` 创建标记目录，再通过 `SESSHUTTLE_TEST_ROOT` 指向它；目录必须在系统临时区。真实 R2/Linux 验收不使用此测试模式。
