# 0.6.0 本机兼容验证与换机验收

安装包使用提交 `48e61b0` 构建。测试使用独立的 Codex 历史目录、应用状态、合成对话和本机应答服务。跨设备传输经过加密及仅监听回环地址的 S3 测试服务。Arch 虚拟机关闭外部网络，通过本机转发交换所选对话。

## 内核与续聊

| 设备 | 实际名单外内核 | 快速验证 | 重开后 |
| --- | --- | --- | --- |
| Apple Silicon Mac | `0.168.0-alpha.1` | 约 0.7 秒 | 直接复用 |
| Arch Linux x86_64，QEMU | `0.168.0-alpha.1` | 约 6.1 秒 | 直接复用 |
| Apple Silicon Mac | `0.164.0-alpha.11` | 约 0.7 秒 | 直接复用 |

官方平台软件包均经过 npm 分发元数据的 SHA-512 核对。上述两个版本均未加入内置名单。快速验证在两个临时 Codex 目录之间通过正式导入代码转移一条样例，向同一线程发送第二轮，检查本机应答服务收到首轮上下文，再启动新的原生进程，读回相同线程 ID、前后两条用户消息和助手回复。

- **同版本往返**。Mac 和 Arch 均使用 `0.168.0-alpha.1`。Mac 上传含 3 轮、图片和工具记录的历史，Arch 导入已有空项目并续写至 5 轮，Mac 下载更新后在原 ID 下续写至 7 轮。两端均读回早期上下文并验证当前工作目录。
- **不同版本往返**。Mac 改用 `0.164.0-alpha.11`，Arch 保持 `0.168.0-alpha.1`，再次完成 3 → 5 → 7 轮。两次往返均保留 Arch 目录中另一条 ID 冲突的对话。测试程序单独核对没有创建手动备份。
- **异常分级**。向真实内核的测试客户端注入两种缺失接口的响应。项目创建接口缺失时，基础续聊验证通过，可选仅导入历史。必要历史接口缺失时，该内核没有获得通过记录。单元测试另外覆盖同版本文件替换、路径别名、旧收据和历史版本警告与缺依赖并存。

## 从安装包操作

Mac 从只读挂载的 DMG 启动英文窗口，Arch 从 tar.gz 解压后在 Xvfb 图形会话中以普通用户启动中文窗口。Arch 使用测试机中的 `/usr/lib/chatgpt/resources/codex`，两端选用独立的空目标历史目录。

1. 选择云端样例并打开导入。所选入口路径已就绪时，窗口直接提供快速验证。手动打开路径检测，零项修改时可点击「使用当前路径，继续导入」。
2. 选择仅导入历史，开始验证，取消后从原处重试。通过后选中的对话、工作目录和项目选择仍在，可查看清单并确认。
3. 第一轮的目标缺少样例使用的模型服务。核对界面显示缺少的服务名，以及目标目录中没有新增该对话的文件或数据库行。在独立测试目录补齐服务配置，从结果处重试并成功导入，同一内核无需重测。
4. 关闭并重新启动安装包，重新连接本机模拟空间，选择同一对话及入口，直接进入预览。真实 R2、用户个人历史及用户 Arch 桌面上的 GPT 侧栏均未用于这次验证。

核心回归在 Mac 通过 63 项，1 项 Linux 专属进程占用测试在 Arch 单独通过。中英文界面共 717 条消息通过检查。包内主程序、渲染界面、四个内置字体及 Linux 压缩包中的应用归档完成核对。
