# Sesshuttle 0.9.0 Windows 11 x64 免安装版验收

## 交付方式

解压 `sesshuttle-0.9.0-win-x64.zip`，双击 `Sesshuttle.exe`。首次选择数据位置并核对完整路径。选择个人主目录以外的位置时，主目录中可见的 `Sesshuttle Location.json` 保存路径和文件夹标识。设置会显示其位置。

Windows 普通账户读出的交付 ZIP 的 SHA-256 为 `f3050076717f6541d3c983fb3da1a36afcf72a0f3dd0b9b5bbdd10a8f61daa47`。ZIP 为 159,642,292 字节。两个可执行文件均为原生 x64 图形程序，ZIP 完整性检查通过。本地包未做代码签名。使用时保留整个解压目录。

## Windows 验收环境

使用 Windows 11 Enterprise Evaluation x64 的独立虚拟磁盘和普通本地测试账户。消息、项目、凭据及模型回复均为合成测试数据，网络只连接本机验收服务。安装包从压缩文件解出后直接运行。AppData 对比覆盖 Roaming、Local、LocalLow，以及账户中额外存在的分支。

首次验证 Codex CLI 0.166.0 时，Windows 在约 34 秒完成样本导入，约 48 秒完成续聊和历史核对。此前的 30 秒上限会在导入中途触发。本版将 Windows 首次验证的等待上限调整为两分钟，保留原有校验和取消操作。

## 首次选择、重开与卸载

程序解压在 C 盘的“文档”，数据选在独立的 D 盘，目录名包含 `Chat 中文 100%`。所有启动均使用普通账户，无需管理员权限。

| 实际操作 | 观察结果 |
| --- | --- |
| 首次打开并取消 Windows 文件夹选择框 | 程序退出，数据目录和主目录位置记录均未创建 |
| 再次打开，选择 D 盘并确认完整路径 | 界面正常显示，数据库出现在 `Chat 中文 100%\Sesshuttle Data\data`，主目录位置记录的标识与数据目录一致 |
| 关闭，再点原来的程序图标 | 直接进入主界面，数据库设备标识相同 |
| 把解压目录搬到 `App 中文 100%` 后双击 | 仍然使用同一份数据库。另一次在窗口尚未载入时关闭，程序正常退出 |
| 退出后，删除解压目录、所选数据目录和可见的位置记录 | Windows 确认三处均已移除 |

同一普通账户在首次使用前、取消选目录后、选定 D 盘后和卸载后的 AppData 清单均为 **7,417 项**。卸载后新增 **0 项**，不可读目录 **0 个**。变化的 12 项均为原有文件，位于微软拼写词典、OneDrive 日志、Windows WebCache 和系统 WebView 缓存目录中。程序目录、选定的数据目录和主目录的位置记录均已删除。

完成跨平台续聊、迁移和解锁后，又核对了一次同一账户的 AppData。共 7,419 项，较初始清单新增三项、减少一项。新增的三项均为 OneDrive 启动日志，其余变化也在微软组件目录内。四次核对均未发现 Sesshuttle 的 AppData 残留。[四次 AppData 核对的逐项差异](0.9.0-windows-appdata.json)

## Mac → Windows → Mac 原生续聊

两台系统均运行官方 Codex CLI 0.166.0。Windows 使用交付 ZIP 的应用执行连接、预览和导入。测试空间提供兼容 S3 的本地服务，模型回复由本地测试服务生成。整个过程使用合成项目和凭据。

| 系统 | 实测结果 |
| --- | --- |
| macOS arm64 发送 | 创建含早期标记和内嵌图片的会话，读取 Mac 工作目录内的测试文件，再加密上传 |
| Windows 11 x64 接回 | 会话标识一致，原图可读，原生项目中能找到该会话。Codex 从保存的工作目录读取了 Windows 独有的测试文件，随后发出新消息并上传。原生记录从 3 轮增至 4 轮 |
| macOS arm64 再接回 | 在新回复前读到 Windows 发回的那条消息和原图，旧标记仍在模型请求中。Mac 核对本机工作目录并继续，记录由 4 轮增至 6 轮，其中一轮为目录核对 |

Windows 通过 Codex 的 `command/exec` 在会话实际记录的工作目录调用系统 `cmd.exe`。另测的 `thread/shellCommand` 未在该评估环境的 30 秒内完成 PowerShell 启动。续聊和图片验证均由原生会话接口完成。
