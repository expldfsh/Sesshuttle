# Sesshuttle 0.4.1 验证记录

交付代码提交为 `80977b4`。测试使用合成历史、临时 Codex 数据目录、回环对象存储和模型服务。个人历史、个人凭据与真实 R2 未用于测试。

## 受冲突影响的操作

- 同一内部 ID 的两份不同历史显示为两份可比较的副本。正常对话即使和其中一份同名，仍可独立上传、移入回收站并恢复。核对恢复后的三份历史逐字节一致。
- 批量上传时排除未决定版本的冲突项。明确选择其中一份后上传，再下载已验证的版本并对比原文。另测先备份、选择一个活动副本，再从目录备份恢复两份原件。
- 删除清单确认后、写入前发生新改动时，拒绝旧清单，保留新内容。重新预览能正常回收并恢复。
- 相关导入、回收、冲突和部分执行检查共 21 项。回环 S3 的另 11 项覆盖六种删除组合、版本选择、共享对象和中断后的剩余操作。类型检查及 650 项双语界面消息检查通过。

## 从 Mac 到 Arch，再回 Mac

使用 Apple Silicon Mac、一次性 Arch x86_64 虚拟机和两边的原生 Codex 内核。Linux 目标数据目录在接收前已放入另一个 ID 的两份冲突历史，传输测试在每次刷新后确认冲突依然存在。

1. Mac 创建三轮合成历史并上传。
2. Linux 导入选定项目。由原生内核按项目列出该对话，读取并继续到五轮。核对早期上下文、项目和本机工作目录，再上传更新。
3. Mac 导入回程版本，读取早期上下文并继续到七轮。环境交接消息由测试用户主动发送。

## 安装包

从 Mac DMG 和 Arch 上解压的 Linux 压缩包启动最终应用。在两边的图形窗口展开扫描问题，比较冲突副本，勾选另一条正常对话，确认操作栏范围，再打开其本机删除清单。Linux 使用测试账号和虚拟显示器。Debian 包核对内部应用内容，未另做 Debian 桌面安装。运行版本均为 0.4.1，校验文件为 `release/SHA256SUMS-0.4.1.txt`。

个人 Linux 上安装的 GPT 客户端侧栏及其实际 R2 连接留待设备验收。项目归属和续聊通过真实内核验证。无法确定历史身份、无法读取共享索引或不能建立安全备份时，写入仍会停止。用户可查看扫描位置，已连接时可单独下载所选云端版本。
