# 0.3.0 删除与恢复验证

本轮所有对话、原生目录、R2 凭据和存储对象均为合成样本。Mac 使用 Apple Silicon，Linux 使用独立的 Arch x86_64 虚拟机。各平台的组合测试都通过正式同步引擎和正式 S3 客户端访问当前机器的回环测试服务。开发期间没有读取或改动用户原有 Codex 历史，也未访问真实 R2。

| 确认的操作 | 本机核对 | 当前空间核对 |
| --- | --- | --- |
| 仅本机 · 移入回收站 | 活动历史和独占图片移入本机回收站，可恢复到相同历史文件 | 两个备份版本继续可读 |
| 仅本机 · 彻底删除 | 活动历史和本次暂存副本被清理 | 另一个设备仍能读取云端备份 |
| 仅云端 · 移入回收站 | 原文件与独占图片保留 | 活动版本移入共享云端回收站 |
| 仅云端 · 彻底删除 | 本机历史与独占图片保留 | 所选版本及独占图片分块被清理，共用分块可读 |
| 本机和云端 · 移入回收站 | 本机回收站可独立恢复 | 云端回收站可独立恢复，恢复云端后本机仍待用户选择导入 |
| 本机和云端 · 彻底删除 | 本机选定历史及本次暂存被清理 | 指定版本及独占分块清理，两侧分别报告完成 |

每种组合都另行检查了另一台设备的独立历史目录。该设备刷新后原始文件逐字节相同，云端空间用量不因刷新改变。项目源文件、其他对话、共享附件及已有整库安全备份均保留。

## 失败与保留边界

- 删除预览后本机附件发生变化、出现新的云端版本，或切换空间时，旧确认不能继续清理。
- 令云端成功后本机被占用，模拟应用重启并只重试本机。已完成的云端记录没有重写。
- 在永久清理中注入云端中断。待处理清单仍可续接，其他写入不能越过清理，另一空间内相同对话 ID 的内容保持完整。
- 本机活动历史已移除、最后清理恢复副本时遇到权限错误，结果明确指出剩余工作。即使这时原位置出现新文件，重试也只清理原回收副本。
- 覆盖仅被另一个回收条目引用的附件、被其他版本嵌入的会话、同一版本清单的双重引用、已有新分支时恢复和两个本机目录共用附件。释放数据前检查全部保留引用。
- 保留原有可恢复删除的依赖保护、损坏或过时清单、恢复冲突、共享路径和链接保护检查。

## 界面与交付

在 Mac 隔离窗口中，从标题旁的「删除对话…」实际走过三种位置及两种方式的选择。永久删除预览展示设备、空间、版本、附件、保留副本和预计释放量，确认框默认未选。随后执行两处回收，核对云端与本机的独立成功结果，先恢复云端、再恢复本机，并查看两处回收站的独立状态。

Mac 的 52 项核心检查通过。Arch 单独执行最终的 16 项删除相关检查，覆盖上述六种组合及异常路径。类型检查及 575 条中英文界面消息检查通过。

三份本地包对应运行代码提交 `1b5a9c1`。Mac DMG 的应用归档、Linux tar.gz 及 Debian amd64 包内容与构建产物核对。两平台的字体、主进程、预加载、渲染界面及许可证随包检查。校验值保存在本地 `release/SHA256SUMS.txt`。Mac 从只读挂载的最终 DMG 启动，读取 3 条合成对话，扫描错误 0；在包内核对了离线预览、明确的对话数量，以及中英文选项与键盘取消。Arch 以普通用户在图形会话中启动最终解压包，经渲染界面到主进程读取 1 条合成对话，扫描错误 0。Debian 包做内容与架构核对，没有单独在 Debian 桌面运行。个人 R2 环境由用户验收。
