# Sesshuttle 0.5.0 隔离验收

应用构建提交为 `0452ffe`。Mac 测试使用 Apple Silicon，Linux 使用隔离 Arch x86_64 虚拟机。所有历史、应用状态和云端对象均为临时合成数据。模拟 S3 只监听本机地址。

- **安装包界面**　从 DMG 启动 Mac 应用，在 Arch 虚拟桌面解压运行 Linux 包。启动时不扫描对话，点刷新后出现三条合成对话。从 13 条已完成记录中选择一条，取消清除后仍有 13 条；确认后剩 12 条，再清空。手动创建备份后检查原因与磁盘占用，恢复后仍只有一份，删除后列表为空。
- **同步接续**　真实 Codex 内核连接模拟模型服务。Mac 创建的同一条历史由 Arch 导入并从 3 轮续到 5 轮，再上传并由 Mac 导入续到 7 轮。检查早期上下文、本机工作目录及三阶段均未出现自动备份。该测试通过内核继续对话，没有操作用户个人的 GPT 桌面端。
- **范围和故障**　确认时以文件清单校验恢复范围；预览之后出现额外文件会停止。复制过程中原始文件发生变化，手动备份失败且无残留备份。清除日志后，已有同步基线仍有效，再次预览无需上传相同分块。运行中任务及待恢复的删除操作仍在。用模拟存储验证本机、云端和两侧删除的六种组合。
- **进程检查**　在 Arch 启动名为 codex、明确设置 CODEX_HOME 的测试进程。写入相同目录被阻止，另一个已确认独立的目录通过。无法确定归属时，写入仍要求退出可能占用目录的应用。Mac 对写入沿用保守进程检查。
