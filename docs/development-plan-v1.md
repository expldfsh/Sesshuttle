# sesshuttle 第一版开发计划

日期：2026 年 11 月 1 日  
关联范围：[第一版需求文档](requirements-v1.md)

## 1 交付方式

以通过验收关卡推进，不先承诺固定工期。以已有内核接续证据为基础，同步推进兼容性、存储协议和桌面界面；局部未验证能力只限制对应写入操作，不阻塞独立功能。第一版的中英文支持属于基础工作，不留到发布前补做。

当前已实现可安装的 0.1.0-rc.1 候选版：桌面界面、R2 适配、加密版本、多目标导入、项目绑定与恢复齐备，完成 Mac 隔离端到端检查和正式同步引擎原生 A→B→A 接续。已生成 Mac 与 Linux 安装包，未连接用户真实 R2 或迁移真实历史。当前进入 M4 集中验收，正式签核仍待真实 R2、Linux 与原生界面验证。证据和限制见[候选版验证记录](validation/m4-candidate.md)。

目标平台为 macOS Apple Silicon、Linux x86_64、Windows x86_64；开发阶段在用户 Mac M3 上自主完成隔离验证；首轮真实双机验收在可安装候选版完成后使用 Mac + Linux，不要求用户在开发过程中频繁配合。覆盖桌面端、CLI 与 VS Code Codex 扩展的对话，提供来源筛选、具体对话选择及用户指定目标入口的跨入口导入。优先接入用户自有 R2 Bucket，不需要额外的关系数据库或网站部署。

## 2 里程碑与依赖

| 阶段 | 目的 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| M0 验证准备 | 确定实际环境和可恢复测试数据 | 设备版本矩阵、脱敏测试会话、备份 | 原始测试数据可恢复，两个目标环境明确 |
| M1 核心接续验证 | 在 Mac 隔离环境完成 A 到 B 再回 A | 最小导出导入工具、验证记录、兼容性决策 | 隔离环境中原生接续与目录验证通过，真实 Linux 验证明确待验收 |
| M2 同步与存储 | 接入首个自有云端后端 | 版本协议、加密、同步、冲突与恢复模块 | 故障与并发测试通过，用户存储往返成功 |
| M3 桌面软件 | 让用户通过界面完成配置和操作 | 三个基础页面、双语资源、设置与凭据管理 | 不编辑配置文件即可完成主要流程 |
| M4 发布验收 | 用户在可安装候选版中配置 R2，集中完成 Mac + Linux 验收 | 双机验收报告、安装包、双语使用指南 | 需求文档 AC01 至 AC15 全部通过 |

M1 的开发关卡采用 Mac 上独立数据目录和不同项目路径的隔离实例验证，不以用户提前操作 Linux 为前提。此结果不能替代真实跨系统验收；可安装候选版可先交付测试，只有实际通过的能力才可声明正式支持。M1 未通过时，继续调查接续问题，不能以界面完成或历史查看代替核心验证。研究发现需要更改产品承诺时，先记录差异并与用户确认，不静默缩小验收目标。

## 3 M0 验证准备

### 3.1 记录真实设备

开发时先记录可自主获取的 Mac M3 环境，Linux x86_64 的实际版本与路径在候选版集中验收时补齐，Windows x86_64 后续单独验收。在仓库建立兼容性记录，填写设备 A、B 的系统及架构、Codex 桌面端与底层运行组件版本、数据目录、账户登录方式和测试项目路径。测试项目在两端必须使用不同绝对路径。

第一版支持哪些系统，由这两台设备及后续实际验收决定。跨平台框架可构建不等于该系统已经支持。没有第二台实体设备时可先使用隔离环境调查，但不能据此勾选最终双机验收。

记录桌面端、CLI 和 VS Code Codex 扩展各自版本、历史位置、来源标记及共享数据关系。对无法确认来源的历史明确标注未知。

### 3.2 创建可检验的测试会话

使用专用测试项目与不含真实秘密的会话，包含：多轮中文和英文消息、一个仅存在于早期对话中的标记、一次工具调用及输出、一次项目文件修改、一项可读取附件。另准备归档会话和分歧会话。三个入口分别建立测试会话，覆盖共享历史去重和来源未知场景。

保留源数据快照和校验清单。不得以真实工作历史作为首次破坏性试验对象，不修改源项目中的只读资料。

## 4 M1 核心接续验证

### 4.1 调查顺序

1. 用当前版本的官方能力列出和读取测试会话，确认完整内容与分页边界。
2. 确认历史、元数据、附件、子会话和恢复状态的实际位置；区分可重建索引与不可丢失数据。
3. 优先验证官方恢复或导入能力；无可用接口时，再研究受版本限制的离线迁移适配器。
4. 证明导入记录能被实际桌面端发现、显示和继续，而非只在独立 CLI 中存在。
5. 证明执行目录改变有效，环境说明能在下一轮工作前被 agent 接收，且目标设备权限没有被放宽。

App Server 的读取和恢复接口是研究入口，不能直接假定 `resume` 会将另一台机器的会话导入本机。官方文档亦包含分页历史行为，需针对当前安装版本调查。[官方文档](https://learn.chatgpt.com/docs/app-server)

### 4.2 最小工具范围

先实现仅面向测试环境的枚举、导出、包校验、导入、备份恢复及环境绑定操作。验证工具继续保留，同时开发正式产品 UI。

先用本地迁移包排除网络变量，证明迁移和恢复可行；M2 再用选定云端存储重复同一条流程。本地包的成功不能代替最终云端验收。

### 4.3 往返验证步骤（开发时隔离模拟，候选版后真实双机复验）

| 步骤 | 操作 | 需要保存的证据 |
| --- | --- | --- |
| 1 | A 在测试项目建立多轮会话，完成一轮后生成一致快照 | 源版本、消息与资源清单、快照校验值 |
| 2 | B 已准备相同项目代码，但路径不同；独立登录 Codex | B 的项目路径、代码版本和登录可用状态 |
| 3 | 将迁移包复制到 B，备份后导入；按验证要求退出或重启 Codex | 导入日志、备份位置、必要操作步骤 |
| 4 | 在 B 的 Codex 原生界面打开对话 | 历史可见性、原消息、工具结果和附件检查 |
| 5 | 设置 B 的执行目录，补充设备与路径环境信息 | 实际绑定值、agent 接收环境的证据 |
| 6 | 用户要求读取当前项目中的验证文件并执行低影响命令 | 实际工作目录与返回内容；仅让 agent 声称正确不够 |
| 7 | 验证 agent 能使用早期对话信息继续任务 | 早期标记验证和任务输出；同时核对历史完整性 |
| 8 | B 新增一轮后导出，A 备份并导入 | B 新版本与 A 导入结果 |
| 9 | A 在原生界面看到 B 新增内容并继续 | A 使用自身路径执行的证据 |
| 10 | 再次导入同一版本并进行一次恢复 | 无重复记录、备份恢复后可续聊 |

### 4.4 通过与失败判定

通过需要同时满足：可见历史完整、原生界面可续聊、执行路径正确、环境说明有效、往返不重复、备份可恢复、两端版本明确。

以下情况不能算通过：只打开导出的文本；只在自建聊天窗口工作；新建对话仅粘贴摘要；模型口头声称路径正确但未执行验证；导入后丢工具结果或测试附件；依赖删除整个 Codex 数据库才能“显示”。

如果需要保留逻辑对话身份但改变本地会话 ID，记录确切行为并验证不会不断创建重复对话。若无法保持原生接续体验，列出问题、可行替代及对产品的影响，先解决或重新商定范围。

### 4.5 跨入口接续验证

建立“来源入口 × 目标入口 × 系统 × Codex 版本”矩阵，区分已验证、不支持和待验证。开发阶段先在 Mac 隔离实例间完成同入口往返，再验证 CLI、VS Code 扩展对话由用户选择导入桌面端的流程；其他目标组合通过验证后开放。

验证来源分类与同步选择、共享会话去重、一次选择多个导入目标、完整历史与附件、实际执行目录、目标权限、重复导入及回传后的逻辑身份。跨入口导入失败不能以摘要新建对话替代。若必要组合不可行，记录影响并与用户确认范围调整。

多目标验证必须覆盖 IDE 备份导入全部已支持入口、Desktop 备份导入 IDE + Desktop、CLI 导入桌面端。确认入口是否共享历史并验证只写入一次、逐入口检查结果；覆盖目标未安装、不支持、单目标失败、部分完成与仅重试失败目标。Mac 开发阶段使用隔离实例与合成数据完成这些检查，真实 Linux 复验留到候选版集中验收。

### 4.6 输出

- 一份可重复执行的双机验证记录与成功、失败案例。
- 版本兼容矩阵和导入所需的关闭、重启步骤。
- Codex 适配方案决策，说明哪些数据必须迁移、哪些字段可调整。
- 后续需要自动化的核心回归用例。

## 5 M2 同步引擎与自有存储

### 5.1 后端选择

比较候选后端的部署负担、凭据管理、并发检测、版本对象存储与成本可见性。首个后端优先采用 Cloudflare R2 Bucket，开发阶段先通过存储适配测试验证协议与故障处理，不要求用户提前创建 Bucket；候选版具备安装包和配置界面后，用户再创建专用 Bucket 并直接在软件中配置；无需额外部署关系数据库。若验证发现不适用，再与用户确认替代方案。首个实现确认后写一份简短决策记录；不提前增加账号服务器或远端关系数据库。

存储适配层提供读取、上传、列表、条件发布和权限测试等能力。能力不足的后端不能退回“最后写入覆盖”而仍声称安全同步。

### 5.2 数据模型

| 实体 | 最少包含 |
| --- | --- |
| 同步空间 | 随机标识、协议版本、加密元数据 |
| 设备 | 稳定标识、显示名、平台、最近成功同步时间 |
| 项目 | 稳定标识、显示名、可选仓库身份 |
| 设备路径绑定 | 项目、设备、工作副本身份、本地目录 |
| 逻辑对话 | 稳定标识、项目、各设备本地会话 ID、来源 |
| 对话版本 | 不可变标识、父版本、内容摘要值、作者设备、资源清单 |
| 同步任务 | 内容范围、同步方向、计划版本、目标入口集合、整体状态、恢复检查点 |
| 入口导入结果 | 逻辑对话、目标设备与入口、共享数据存储标识、目标版本与已导入版本、同步状态、导入状态、接续验证结果、错误码、备份引用 |

敏感字段放在加密内容中。时间为展示和审计信息，父版本及内容摘要用于判断相同、领先、落后或分歧。无法证明版本关系时按冲突处理，不猜测覆盖方向。

### 5.3 提交与恢复协议

1. 为静止会话获取一致快照；无法取得时标记使用中，不强制结束任务。
2. 校验资源清单，封装并加密不可变版本。
3. 先上传所有依赖对象并验证，再条件更新对话的版本指针。
4. 更新前发现云端已变化则重新比较；不得覆盖其他设备已经发布的新版本。
5. 下载进入临时区，完成解密和完整性验证后才准备导入。
6. 再检查本机是否变化或正在使用，生成备份，然后按已验证适配器导入。
7. 只有验证 Codex 可识别导入结果后，才记录对应完成状态；重启待验证状态需单独显示。

导入多文件不能假装是一次文件重命名即可原子完成。实现任务日志与恢复步骤，覆盖进程在任一步骤退出的情况。失败上传留下的未引用对象不应被视为已发布版本；第一版不自动垃圾回收。

多目标导入按共享数据存储协调写入，避免重复写入或相互覆盖；每个入口独立验证并记录结果。任务允许部分成功，不承诺跨入口整体原子提交；单目标失败不撤销或隐瞒已成功目标。重试仅处理失败或未完成目标，并重新核对版本和使用状态。云端发布结果、下载结果、导入结果与入口可续聊状态分开保存。

R2 条件写入可用于版本指针竞争检测，但不提供整个多对象流程的一次性事务；需在应用协议中保证先对象后发布。[R2 一致性说明](https://developers.cloudflare.com/r2/reference/consistency/)

### 5.4 不依赖全局锁的安全边界

软件无法保证用户不会在两台原生 Codex 中同时续写。因此默认指导顺序切换设备，协议仍必须检测分歧并保留两份。第一版不依赖“用户一定遵守单设备续写”来防止数据丢失，也不自动拼接不同分支。

### 5.5 加密与凭据

选用成熟库，明确密钥创建、存储、恢复、错误密钥处理与格式版本。先完成核心安全路径，不自创密码算法。使用专用凭据访问指定存储，凭据不进入代码、诊断日志和迁移包。

## 6 M3 桌面界面与双语

### 6.1 建议技术栈与确认关卡

正式实现采用 Electron + React + TypeScript，Vite 构建界面，Node 内置 SQLite 保存本机索引，AWS SDK 访问 R2，系统凭据服务保护本机密钥。选择理由与代价见 [桌面技术栈决策](decisions/0002-desktop-stack.md)。旧 Tauri 基线已被替换。

验证重点是原生进程交互、文件保护、系统凭据、主进程和界面的受限调用边界及三平台打包。业务模块与界面分离，避免框架决定对话格式或同步协议。

最终软件通过应用图标启动独立窗口。界面资源随安装包分发，不要求用户打开浏览器、启动开发服务器或安装开发工具链。React 用来绘制桌面窗口中的界面，本机扫描与同步由后台业务模块执行，耗时任务不得阻塞界面。

建议模块边界：Codex 适配、同步引擎、存储适配、加密与凭据、项目环境、桌面界面、本地化。界面通过受限能力调用本地操作；展示对话时按不可信文本处理，不执行嵌入脚本。

### 6.2 开发顺序

1. 建立中英文翻译资源和统一日期、数字、错误展示接口。
2. 完成设置：语言、设备、Codex 目录、存储连接、加密恢复。
3. 完成对话列表：扫描、按来源与项目筛选、具体对话或范围选择、预览、差异与同步计划。增加内容范围、上传/下载/双向同步选择以及目标入口多选，支持选择全部已支持入口，仅开放已验证组合。详情分别显示云端备份和各入口的同步、导入、可续聊状态；提供逐入口进度、部分完成提示和失败目标重试。
4. 接入任务进度、取消或安全暂停、重试、冲突保留和备份恢复。
5. 完成项目路径绑定、文件状态检查和在 Codex 中继续入口。
6. 两种语言逐项走查首次使用、断网、冲突、缺失路径和恢复流程。
7. 按用户确认的 Comic Neue + 霞鹜文楷 / Tokyo Night Moon 基线统一界面，去除装饰和重复说明；字体内置安装包，核对许可证与离线资源，检查 16px 正文、至少 13px 辅助字和中英文布局。
8. 将所有选择框替换为应用内菜单，抽离共享主题配置和本机主题标识；实查鼠标、键盘、焦点、长选项、滚动与窗口边缘定位，当前仅开放 Moon 主题。

产品文案先集中管理，禁止把可见中文或英文散落在业务逻辑中。翻译键集合一致性进入检查流程；用户数据不自动翻译。第一版默认简体中文与英文，不扩展为额外语言任务。

## 7 M4 验证矩阵与发布

| 类别 | 必须覆盖 |
| --- | --- |
| 真实闭环 | A 上传、B 导入接续、B 上传、A 导入接续，全部经过选定云端 |
| 版本关系 | 相同、单端新增、双端分歧、首次加入、重复同步、设备时钟不一致 |
| 一致性 | 扫描时增长、同步预览后变化、两个设备同时发布、导入前目标被续写 |
| 故障 | 上传或下载断网、权限不足、密钥错误、校验失败、磁盘空间不足 |
| 恢复 | 导入中退出、重启后重试、备份恢复、已上传但未发布版本 |
| 内容 | 长历史与分页、归档、工具结果、附件、子会话依赖和缺失资源报告 |
| 环境 | 路径不同、目录缺失、中文与空格路径、Git 状态不同、非 Git 项目 |
| 来源与入口 | 桌面端、CLI、VS Code 扩展来源识别与未知来源；共享数据去重；选择同步范围、方向与多个导入目标；IDE 到全部已支持入口、Desktop 到 IDE + Desktop；逐入口状态、共享存储单次写入、部分失败与定向重试；跨入口完整接续 |
| 兼容 | 所有声明支持的系统与 Codex 版本；未知版本停止写入 |
| 语言 | 中英文全流程、切换后保留状态、英文长文案、日期时区与错误解释 |
| 数据保护 | 远端不可直接读正文、日志无凭据、目标权限不扩大、连接错误不触发删除 |

测试重点是数据丢失、版本分歧、接续行为和环境正确性。UI 不要求大量镜像实现的测试；关键用户流程需实际走查。

性能以公开测试样本记录：会话数、总大小、首次扫描、二次扫描、传输时间和界面响应情况。第一版至少避免扫描或传输阻塞界面，支持进度查看；具体性能预算在获得真实样本后确定，不编造速度承诺。

发布必须提供已验收平台的可安装包，以及简体中文和英文快速开始，覆盖自备存储、密钥恢复、同步、路径映射、冲突和已知限制。首次下载、系统权限提示与启动过程也需要在干净环境验证。
