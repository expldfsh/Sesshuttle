# Sesshuttle 0.9.1

这一版修复 0.9.0 中程序放在某些文件夹里就完全无法使用的问题，并补上 Windows 第一次打开时缺少的提示。同步格式和云端布局没有变化，可以直接替换旧版本。0.9.0 发布时没有附说明，它带来的变化也列在下面。

## 0.9.0 起的新内容

- **Windows 11 x64 免安装版。** 解压 ZIP，双击 `Sesshuttle.exe`。可以检测安装在 Windows 上的 Codex CLI、商店版 GPT 桌面端和 VS Code 扩展，导入后在其中继续对话。
- **自选数据文件夹。** 第一次打开时选择保存 `Sesshuttle Data` 的位置，设置、备份、回收站和临时文件都在其中。从 0.7.3 升级时，可以把旧数据和已保存的连接凭据迁移过来，核对后再清理旧位置。

## 修复

- **程序所在文件夹的名字含 `%`、`[`、`]` 或 `~` 时无法使用。** 窗口只显示「无效操作」，所有功能都不可用。Mac 和 Linux 上同样会发生。
- **导入过的对话点「继续」时提示数据或设置发生变化。** Codex 数据目录的路径写法与系统给出的不一致，或商店版 GPT 桌面端更新之后，都会这样。现在只有设置确实改过时才会提示，并说明改了什么、去哪里核对。
- **快速验证或导入已经完成，却因为清理临时文件失败而报错。** Windows 上文件刚写完时可能被短暂占用，现在会稍等再试，清理不掉的留到下次启动处理。
- **连接存储不经过系统代理。** 现在跟随系统的代理设置，使用 HTTP 代理时经它建立加密连接。
- 窗口、任务栏和任务管理器显示 Sesshuttle 自己的图标和名称。
- 查看项目的 Git 状态时不再闪出命令行窗口。
- 路径输入框可以直接粘贴带引号的路径，例如 Windows「复制文件地址」得到的。
- 选择 GPT 桌面端的 Codex 程序时，文件选择窗口最多等待几秒就会打开。
- 英文界面下，对话详情的「⋯」菜单在默认窗口大小时可能被截断，点不到「删除对话…」。现在菜单更宽，放不下时可以在菜单内滚动。

## 更清楚的提示

- **启动失败会说明原因。** 解压不完整或文件被安全软件移走时，`Sesshuttle.exe` 会指出缺少的文件。直接打开 `sesshuttle-runtime.exe` 时，会提示改为打开 `Sesshuttle.exe`。
- **数据文件夹被删除后可以重新开始。** 在选择原文件夹的窗口点取消，再确认改用新的空白数据文件夹。
- **CLI 的「继续」失败时终端窗口会保留**，按任意键关闭，可以看到 Codex 给出的原因。
- 第一次选择数据文件夹的窗口跟随 Windows 的显示语言。
- 使用指南新增「Windows 第一次打开」：SmartScreen 提示怎么放行、智能应用控制会直接阻止未签名程序、WSL 中的 Codex 暂不支持。

## 须知

- 安装包没有代码签名。Windows 第一次打开时如果看到「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
- 这个 ZIP 在发布前由发布流程在 Windows 上解压并打开过，包括放在名字带特殊字符的文件夹里。三个应用的完整续聊验收是在 0.9.0 上做的。
- 只设置了 SOCKS 代理时仍然直接连接存储。

# Sesshuttle 0.9.1

This release fixes 0.9.0 being unusable when the program was kept in certain folders, and adds the guidance that was missing for the first start on Windows. The sync format and the cloud layout are unchanged, so you can replace the previous version. 0.9.0 was published without notes; what it introduced is listed here too.

## New since 0.9.0

- **A portable build for Windows 11 x64.** Extract the ZIP and double-click `Sesshuttle.exe`. It detects the Codex CLI, the Store version of the GPT desktop app and the VS Code extension installed on Windows, and continues imported chats in them.
- **A data folder you choose.** On the first start you choose where `Sesshuttle Data` is kept; settings, backups, trash and temporary files live there. When upgrading from 0.7.3 you can copy the previous data and saved credentials, check them and then clean up the old location.

## Fixes

- **The app could not be used from a folder whose name contains `%`, `[`, `]` or `~`.** The window only showed “Invalid action” and nothing worked. This also happened on macOS and Linux.
- **Continue on an imported chat said that data or settings had changed.** This happened when the Codex data folder was spelled differently from the form the system reports, and after every update of the Store version of the GPT desktop app. The notice now appears only when a setting really changed, and says which settings to check and where.
- **A quick check or an import that had finished was reported as failed because temporary files could not be removed.** On Windows a file can be busy for a moment after it is written. The app now waits and tries again, and leaves what it cannot remove for the next start.
- **Storage requests ignored the system proxy.** They now follow the system proxy settings and tunnel the encrypted connection through an HTTP proxy.
- The window, the taskbar and Task Manager show Sesshuttle's own icon and name.
- Reading a project's Git state no longer flashes console windows.
- Path fields accept a path pasted in quotes, such as one copied with **Copy as path**.
- The file chooser for the GPT desktop app's Codex runtime opens after a few seconds at most.
- In English, the **⋯** menu of a chat could be cut off in a window of the default size, so **Delete chats…** could not be reached. The menu is wider now and scrolls inside itself when it does not fit.

## Clearer guidance

- **A failed start says why.** If the ZIP was not extracted completely or security software removed a file, `Sesshuttle.exe` names the missing file. Opening `sesshuttle-runtime.exe` directly tells you to open `Sesshuttle.exe` instead.
- **You can start over after a data folder was deleted.** Cancel the window that asks for the original folder, then confirm starting with a new, empty data folder.
- **The terminal window stays open when Continue for the CLI fails**, until you press a key, so Codex's own message can be read.
- The first folder question follows the display language of Windows.
- The guide has a new section on opening the app on Windows for the first time: how to get past SmartScreen, that Smart App Control blocks unsigned programs outright, and that Codex inside WSL is not supported yet.

## Good to know

- The packages are not code-signed. If “Windows protected your PC” appears the first time, choose **More info**, then **Run anyway**.
- Before publication the release workflow extracted this ZIP on Windows and opened the app, including from a folder with special characters in its name. The full continuation test with all three apps was done on 0.9.0.
- With only a SOCKS proxy set, the app still connects to storage directly.
