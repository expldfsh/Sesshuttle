# sesshuttle 第一版需求文档

文档修订 0.6 · 2026 年 11 月 3 日

## 下一版约束：所有用户数据操作均由用户发起

本节取代下文中有关自动备份、后台刷新及自动恢复操作的旧约定。启动、连接、打开页面、预览、文件变化和重启均不得触发备份、下载、导入、上传、同步、删除、清理、重试或续跑。显示已保存的界面状态可以直接进行；重新扫描本机或查询云端由用户点击刷新。预览只读，确认仅授权界面列明的动作、对象及目的地。

创建备份必须由用户单独选择并确认，普通导入、恢复整份备份、解决冲突和替换历史均无例外。涉及覆盖时展示影响和缺少恢复点的后果，提供手动创建备份和取消入口。无法安全完成时停止并说明原因。完成明确动作所必需的校验和原子写入不另建可恢复的历史副本。

已确认 0.3.0 交付范围（含六种删除组合）。开发隔离验证已完成，用户设备最终验收见[验收步骤](guides/zh-CN/linux-acceptance.md)。

## 1 产品目标

提供一个可安装的桌面软件，让用户连接自己拥有的云端存储，自动发现本机 Codex 历史，与云端比较后手动同步，并在另一台电脑的正确项目目录里继续原对话。

第一版必须能够日常使用。只实现对话备份、上传下载或历史查看，不满足发布要求。界面可以简洁，但配置、状态、失败处理和恢复入口必须完整。

### 1.1 已确定的原则

- 用户自备存储，在软件界面填写连接信息；不要求注册本产品账号。
- 首次启动和手动刷新时扫描本机并检查云端；同步操作由用户主动触发。
- 支持选择部分对话和同步全部范围内的对话。
- 必须显示本机与云端的差异、更新时间和来源设备。
- 必须支持设备识别、本机工作目录绑定，换机说明由用户自行提供。
- 第一版即提供简体中文和英文；视觉打磨可后续迭代。
- 数据完整性优先：冲突保留两份，导入前备份，失败不破坏现有对话。

### 1.2 已确认范围与待验证选择

正式名称为 sesshuttle，沿用仓库现有 MIT 许可证。目标平台为 macOS Apple Silicon（首轮使用 M3）、Linux x86_64 和 Windows x86_64；首轮真实双机验证使用 Mac + Linux，Windows 后续单独验收。目标平台不等于已经支持，仅声明实际通过验证的系统与 Codex 版本。

对话来源覆盖 Codex 桌面端、CLI 和 VS Code Codex 扩展。支持按来源和具体对话选择同步，并允许用户一次选择一个或多个跨入口导入目标。各入口可能共享底层数据，来源识别、去重与各导入组合均需实测。

首个云端后端使用用户自有 Cloudflare R2 Bucket。用户已创建空间，两台设备已连接，Linux 已能看到一条云端对话。本轮开发用独立测试存储，最终在用户现有空间验收。用户只需安装桌面应用和配置对象存储，存储接口保留扩展能力。

最低 Codex 版本、实际导入能力和正式技术栈待核心验证后确定。Tauri 2、React、Rust 等仅为候选；可根据跨平台兼容、本机能力、开发维护成本、打包便利性和运行体验选择更合适方案。正式采用或切换前向用户说明收益、代价并确认。

### 1.3 桌面软件交付要求

- 最终交付可安装、通过应用图标启动、拥有独立窗口的桌面软件。
- 日常使用不要求用户打开浏览器、启动开发服务器或安装前端与 Rust 开发工具链。
- 本机历史扫描、文件夹选择、备份恢复和 Codex 接续由桌面应用提供；云端连接仅承担所配置的存储职责。
- 无网络时仍可启动应用、查看本机历史和修改本机设置；云端检查与同步需连接网络。
- 界面可采用网页技术并嵌入桌面窗口。React 负责界面，桌面框架负责窗口与本机能力；这不改变桌面软件的交付要求。
- 各目标系统的运行依赖由安装或首次启动流程检测，并给出明确处理方式；仅发布实际验收的平台。

## 2 用户的完整使用流程

1. 电脑 A 安装软件，选择语言，设置设备名称。
2. 自动检测 Codex 数据位置；用户可通过目录选择器修改。
3. 连接自己的存储，创建同步空间和加密密钥，保存恢复材料。
4. 查看扫描结果，勾选对话并上传。
5. 电脑 B 安装软件，连接同一存储并导入加密密钥，加入已有同步空间。
6. 按桌面端、CLI、VS Code 扩展等来源筛选云端对话，选择具体条目或整个范围；选择导入目标后下载并导入本机 Codex。跨入口导入由用户明确选择，例如将 CLI 或扩展对话导入桌面端。
7. 为关联项目选择电脑 B 上的实际文件夹。
8. 检查文件状态，进入 Codex 原生界面继续工作；用户自行说明环境，命令实际在 B 的项目目录中运行。
9. B 将新增内容上传；A 下载后能看到 B 的新增轮次并继续。

允许经验证需要退出或重启 Codex 的导入流程，但软件必须解释原因并提供明确步骤。若迁移只能生成摘要或创建无原始历史的新对话，不能判定上述流程成功。

## 3 第一版范围

| 必须提供 | 后续版本考虑 |
| --- | --- |
| 一个经验证的自有存储后端 | 更多对象存储、WebDAV 或数据库后端 |
| 本机扫描、云端检查、差异列表 | 实时监听与无人值守自动同步 |
| 手动上传下载及本机导入 | 更精细的传输优化 |
| 设备、项目路径和接续环境管理 | 更多 agent 适配 |
| 冲突保留、失败重试、版本恢复 | 对话分支可视化与高级合并 |
| 加密及凭据保护 | 多用户团队权限管理 |
| 简体中文和英文桌面界面 | 其他语言、主题和视觉定制 |
| 实际目标设备的安装包 | 尚未验收的平台 |

第一版不负责项目源码同步、依赖安装、终端进程迁移、登录身份迁移和运行中任务迁移。项目文件由用户通过 Git 或现有方式同步；软件检查差异，不自动提交、切分支、覆盖文件或执行旧对话命令。

## 4 功能需求

### FR01 首次配置与本机发现

- 提供语言选择、设备命名、Codex 数据位置、存储连接、加密配置和首次扫描步骤。
- 每个安装实例生成稳定设备标识；修改名称不改变标识。
- 检测到多个数据位置时由用户选择；支持自定义位置。
- 显示已检测的 Codex 版本、兼容状态、扫描范围和失败原因。
- 未配置云端或网络不可用时，仍可浏览本机扫描结果。
- 未知存储格式只读展示可识别信息，禁止尝试破坏性导入。

### FR02 用户自有存储配置

- 在界面选择受支持的存储类型，填写该类型要求的地址、凭据、Bucket 或目录、同步空间信息。
- 提供测试连接、保存、修改和断开入口。测试必须区分认证、读取、写入失败；测试写入只操作自己的临时对象。
- 加入已有空间前验证空间身份和加密密钥，显示已有对话与设备摘要。
- 连接失败、权限不足或密钥错误不能被解释为“云端为空”。
- 切换存储时创建独立的同步状态，重新预览差异，不把旧存储的删除或同步记录套到新存储。
- 断开连接不会删除本机历史或远端数据。

### FR03 对话扫描与差异展示

- 启动时自动扫描并检查云端，提供刷新按钮和最后成功检查时间。
- 扫描支持范围内的普通与归档对话。显示无法读取的记录及原因，不能静默漏掉后声称“全部完成”。
- 列表至少包含标题、项目、本机更新时间、云端更新时间、来源设备、同步状态和可续聊状态。
- 支持标题搜索、按项目和状态筛选、勾选单条或当前范围全部对话。
- 对话详情显示历史预览、版本关系、附件完整性和项目目录；新增轮次数仅在适配器可准确计算时展示。
- 时间用于展示，版本关系与内容校验用于同步判断；云端上传时间与内容更新时间分别保存。
- 显示完整时间及时区；相对时间不能是唯一信息。

### FR03a 对话来源与自定义导入

- 支持桌面端、CLI、VS Code Codex 扩展来源筛选，结合项目、状态和具体条目决定同步范围。
- 来源和导入目标分别保存；跨入口导入不改变原始来源记录。
- 对共享底层历史的入口识别同一逻辑对话，避免重复展示、上传和导入；证据不足时显示来源未知，不猜测分类。
- 提供跨入口继续选项，由用户一次选择 Desktop、CLI、IDE（VS Code Codex 扩展）中的一个、多个或全部已支持目标入口，并绑定本机项目目录；同步本身不自动转换入口或开始执行任务。
- 展示当前版本已验证的来源到目标组合；不支持或未验证的组合说明原因，不执行未经验证的写入。
- 用户可按需要选择导入目标；第一版必须验证 CLI、VS Code 扩展对话导入桌面端继续的场景，其他组合按实际验证结果开放。
- 跨入口接续沿用完整历史、资源校验、备份、权限和执行目录要求，不降级为摘要续聊；重复导入保持幂等。
- 将“同步内容”“同步方向”和“导入目标”分别选择：内容为单条、多条或当前范围全部对话；方向为上传备份、下载导入或同步双方更新；目标为当前设备一个、多个或全部已支持入口。“全部对话”不等于“全部入口”。上传备份无需选择本机导入目标。
- 支持用户选择 IDE 来源备份导入本机全部已支持入口，以及 Desktop 来源备份导入本机 IDE + Desktop 等组合；未验证或不支持的目标禁用并说明原因，不静默缩减选择。
- 同步预览逐条列出来源、方向、目标入口、目标版本、路径和预计动作；用户确认后执行。同步双方更新仍遵守版本关系与冲突保留规则，不自动合并分歧。
- 每条对话分别展示云端备份状态及各入口相对于选定版本的同步和导入状态。入口状态至少区分：不存在、待导入、有更新、已导入待验证、已同步且可继续、冲突、使用中、失败、未安装或不支持，并展示原因与可用修复动作。
- 上传成功仅表示云端备份完成，下载成功仅表示取得数据；只有目标入口识别该版本且接续前置检查通过，才能标为该入口已同步且可继续。
- 多目标执行逐入口报告结果，允许部分成功；一个目标失败不抹掉其他目标的成功记录，整体显示部分完成。用户可只重试失败目标，已完成目标不重复导入。
- 多入口共享底层历史时只进行一次必要的数据写入，并分别验证各入口的可见与可续聊状态；不能因写入共享数据就把所有入口标为成功，也不能为每个入口制造重复对话。


### FR04 同步规则

| 状态 | 界面含义 | 默认处理 |
| --- | --- | --- |
| 仅本机存在 | 云端尚无此对话 | 上传 |
| 仅云端存在 | 本机尚无此对话 | 下载、校验、导入 |
| 本机有更新 | 本机在共同版本上新增内容 | 上传新版本 |
| 云端有更新 | 云端在共同版本上新增内容 | 下载、校验、导入 |
| 已同步 | 两端对应相同版本 | 无操作 |
| 两边均有修改 | 两端从共同版本分别产生变化 | 保留两份分支，等待选择 |
| 使用中 | 无法取得一致快照或安全导入 | 延后处理，说明原因 |
| 待处理 | 密钥、格式、附件、路径或权限有问题 | 展示修复动作 |

- 同步前展示上传、下载、冲突、跳过条目及预计体积；执行前再次确认版本未变化。
- 支持同步选中和同步全部。同步全部仍遵守用户配置的范围，并单独报告冲突和失败。
- 显示每条对话的扫描、传输、校验、导入结果，不把下载完成等同于可续聊。
- 同步重复执行不制造重复记录；中断或失败后可以重试。
- 同步期间对话继续变化时，不发布不完整版本，不覆盖已经产生的新内容。
- 第一版不自动传播删除，不因云端为空或本机文件消失删除另一端。归档与删除分别处理。
- 冲突不按最后修改时间自动覆盖，也不拼接两个独立对话尾部。用户选择接续分支后，另一份仍可恢复。

### FR05 对话内容与完整性

- 对支持的 Codex 版本，保留已持久化的用户和 agent 消息、工具调用与结果、会话元数据及恢复所需的数据。
- 检查恢复相关的附件、引用资源及子会话依赖；能获取且属于同步范围的内容随会话保存。
- 不把日志里提到的任意项目文件都当成附件自动上传。
- 对缺失、过大或不能迁移的资源列出具体项。仅本地图片缺失或用户明确不包含图片时，可逐项确认后导入接续；标记“部分附件缺失”，不声称图片完整。缺少关键历史、必需父历史、数据损坏或未知资源格式时仍阻止导入。
- 用户仍可选择仅备份不完整对话；仅备份成功不能替代原生接续验证。允许缺图的导入必须保留全部文字、工具历史及原始备份，只在目标副本替换已确认的图片引用，并校正分页位置。
- “完整历史”指源设备实际保存并能获取的数据；不承诺还原已删除内容或模型未持久化的内部状态。

### FR06 设备和项目路径

- 项目采用稳定标识，与任一电脑的绝对路径分离。
- 保存项目在各设备上的路径绑定；本机绑定不能被另一设备的路径自动覆盖。
- 可依据 Git 仓库信息推荐匹配，但首次绑定由用户确认；非 Git 文件夹也支持手动绑定。
- 同一仓库的多个工作副本或 worktree 不能仅因远端地址相同而合并；会话需绑定到正确工作副本。
- 缺少目录时禁用继续入口，并提供选择本机文件夹的动作。
- 历史文本中的旧路径保持原样；只调整经适配器确认的执行元数据，供目标入口使用。

### FR07 在当前设备继续对话

- 检查对话导入成功、目标版本兼容、所需资源齐全、项目路径有效。
- 显示执行设备、系统、项目路径；Git 项目额外显示分支、提交版本和未提交修改摘要。
- 代码版本不同可经用户明确选择继续；目录缺失或项目绑定错误必须先解决。
- 实际执行目录必须与本机绑定一致，不能只给 agent 一段文字提示。
- 用户自行决定何时告诉 Codex 已换电脑、如何对应新旧文件夹，以及提供哪些文件。绑定目录只设置本机执行位置。
- Sesshuttle 在首次导入、重复导入、切换入口及继续对话时均不向对话或模型上下文追加设备、系统、目录映射说明。保留历史中原有的消息及原生 Codex 自身的环境机制。
- 保留目标设备原有权限和审批设置，不继承源设备更宽松的权限。
- 同步本身不发送新任务、不自动续跑旧命令；继续操作由用户触发。
- 第一版以当前设备本地执行为范围；数据模型区分操作设备和执行设备，远程执行支持留待后续。
- 若底层必须改变会话 ID，记录逻辑对话与各端会话 ID 的关系，并清楚展示迁移结果；不能静默退化成摘要续聊或不同任务。

### FR08 备份与恢复

- 每次改变本机 Codex 数据前生成可恢复备份；备份失败则停止导入。
- 提供从界面查看备份与恢复的入口，恢复也需满足 Codex 不在冲突写入的条件。
- 远端保存不可变历史版本，失败操作不得改变已提交版本。
- 第一版不自动清理用户历史版本；显示占用情况，清理策略后续单独实现。
- 删除设备记录仅影响设备列表，不等于撤销已泄露的存储凭据。凭据撤销需在存储提供方完成，界面需解释这一点。

### FR09 安全与数据归属

- 对话正文、标题、项目路径和敏感元数据在上传前加密；对象名称不直接泄露标题或本机路径。
- 使用成熟加密库与认证加密，不自创加密算法。远端仍可能观察到对象数量、大小和访问时间。
- 访问凭据与加密密钥分开管理，优先存入系统凭据管理器；系统能力不可用时不静默退回明文文件。
- 提供恢复密钥导出和新设备导入；明确密钥丢失后无法由开发者恢复加密内容。
- 不同步 Codex 登录凭据、API key 或运行权限；每台设备独立完成 Codex 登录。
- 默认无遥测。诊断日志不记录凭据和完整对话；用户主动导出诊断时先预览。
- 网络默认只连接用户配置的存储。软件首次写入或导入前展示具体操作范围。

### FR10 中英文支持

- 第一版支持简体中文 `zh-CN` 和英文 `en`。首次启动跟随系统，非中文系统默认英文；设置中可手动切换并持久保存。
- 语言偏好属于本机设置，不因另一台电脑选择不同语言而被覆盖。
- 所有产品界面文本使用翻译资源，包括首次配置、菜单、表头、空状态、进度、错误、恢复、确认提示与安装使用指南。
- 切换语言不重置同步任务、连接设置或选择状态。
- 用户对话、标题、设备名称和路径不自动翻译。底层错误原文可展开查看，解释与建议提供双语。
- 格式化日期、时间、数量和文件大小；英文复数使用本地化规则，不通过字符串拼接实现。
- 传输协议与错误码使用稳定标识，不能依赖某一种界面语言。
- 第一版须通过中英文两套关键流程检查，包含中文路径、空格路径、英文长文案和错误提示。

### 5.5 建议的桌面技术方案

正式实现为 Electron + React + TypeScript，构建工具为 Vite；本机逻辑使用 Node，索引使用 SQLite，系统凭据服务保护秘密，AWS SDK 连接 R2。中文与英文文本集中管理，使用 Intl 格式化日期。

技术栈选择与体积代价见[桌面实现决策](decisions/0002-desktop-stack.md)。界面资源和运行环境随安装包分发，无需浏览器、开发服务器或开发工具链。业务模块与桌面框架分离，产品验收目标不因框架调整而变化。

### 5.6 字体、配色与信息密度

- 界面英文使用 Comic Neue，中文使用霞鹜文楷（LXGW WenKai），正文与强调字重均随安装包分发；不要求用户安装字体，不连接在线字体服务，离线和未安装字体的设备上仍按同一资源显示。
- 语言、同步状态和历史版本选择使用软件内置下拉菜单，展开层也采用相同主题与字体；支持鼠标、方向键、Home/End、回车、Esc、Tab 和点击外部关闭，菜单靠近窗口边缘时调整位置。
- 颜色集中为语义化主题配置；主窗口、弹窗、菜单、焦点与状态共用配置，预留主题标识和本机保存能力。当前只提供 Tokyo Night Moon，不增加未经确认的其他主题。
- 整体使用 Tokyo Night Moon 配色。正文默认 16px，表单/操作主要采用 15–16px，辅助文字不低于 13px；保证足够行距、文字对比度和清晰的键盘焦点。
- 左上角只保留项目名称；移除装饰图标、标语、重复标题和与核心操作无关的说明。保留来源、同步范围、方向、目标入口、逐入口状态、错误、密钥恢复和写入确认等必要信息。
- 在中英文、较窄窗口、长标题/路径、错误和确认对话框中实际检查布局。缩小窗口时调整结构和滚动，不靠缩小文字挤压内容。

## 6 存储方案边界

本机索引由软件自动维护，用户配置的是云端持久存储。第一版不要求用户额外部署传统数据库或本产品的账号服务器。

R2 是 S3 兼容对象存储，适合存放版本文件与附件，不等同于关系数据库。若选择 R2，可采用“本机索引 + 加密版本对象 + 同步清单”；其条件写入能力可用于避免并发覆盖，但协议仍需处理多对象提交和失败恢复。[R2 工作方式](https://developers.cloudflare.com/r2/how-r2-works/) · [R2 一致性说明](https://developers.cloudflare.com/r2/reference/consistency/)

优先验证 R2，具体接入方案在核心迁移验证后确定；若发现能力不足或有更合适方案，先与用户讨论。首个后端必须满足认证访问、对象完整读写、并发更新检测和故障恢复需求。是否增加服务端索引数据库，取决于实际规模，不作为第一版前提。

## 8 兼容性依据与约束

Codex 官方 App Server 文档提供会话枚举、历史分页读取、恢复及执行目录相关能力。这些能力构成适配的研究入口，并不保证存在可跨任意版本、跨设备直接导入的稳定协议。必须以实际版本的双机验证为准。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)

不得预设所有历史都只在 JSONL 中，也不得假定任何本机数据库都可以删除后无损重建。只有经版本检查、备份和往返测试证明可行的导入方式，才进入第一版支持列表。


## 9 开发测试与用户验收方式

开发期间优先在用户 Mac 上自主完成安全、隔离的测试，不要求用户频繁配合 Linux 操作。现有项目文件和 Codex 历史不得因测试被修改、删除或损坏；写入与故障测试仅使用独立测试数据和进程，不能影响日常 Codex 或系统稳定性。隔离无法确认时不进行写入测试。

先交付包含安装包、R2 连接配置及完整主要操作流程的版本，用户再用现有空间在 Linux 集中验收。R2 为对象存储，无需额外配置关系数据库。Mac 上的隔离验证用于推进开发，不能代替真实 R2 与跨系统验证；未通过的验收项保持待验证，全部必须项通过后才称为正式可用第一版。Windows 后续单独完成实际验收。

### 0.3.0 删除与恢复（已确认）

删除有两个独立选项。位置为本机、当前 R2 空间或两处；方式为移入各自回收站或彻底删除。回收站为默认，永久选项每次重新选择。删除不向其他设备发送本地删除命令。已导入的其他设备可以继续原对话；云端无可用版本时，新设备不能再下载该版本。刷新不触发上传或下载。

- 从标题旁和多选栏直接进入「删除…」。预览写明设备名、同步空间、直接勾选及附带的对话、原生项目、依赖、共享本机历史目录的所有已配置入口。附件列出路径、归属、处理或保留原因。按本机与云端分别展示结果。
- 云端允许勾选全部或若干历史版本。展示来源设备、时间、大小、当前版本和分支。删除当前版本前明确剩余可导入版本或分歧。嵌在其他备份的历史、回收站、既有整库安全备份须说明会保留。共享对象不得误删，空间估算区分逻辑大小和可释放对象。
- 本机及云端回收站均支持显式恢复或永久清理指定条目。云端回收站可从同一空间的另一台设备查看和恢复。恢复遇到新内容时保留现有版本与分支；恢复云端不触发本机导入。永久删除只针对清单中的条目。
- 两侧预检后再执行，失败、中断或过期不扩大原范围。任务持久显示每侧成功、未执行、失败或待收尾，重试只处理尚未完成的侧。并发上传、共用数据、不同同步空间、没有连接及旧格式备份均需纳入保护。
- 本轮全部删除测试只使用隔离数据、本机模拟存储和第二台模拟设备。交付 Mac ARM64、Linux x86_64 安装包，按阶段本地提交，不 push。

## 跨设备配置、系统授权与操作反馈（0.4.0，已确认）

### 目标与边界

用户在 Mac 上已有可用的 R2 连接。第一次在 Linux 上打开 Sesshuttle，应能靠界面完成导入配置、连接、找到云端对话、导入目标入口并继续聊。反向迁移同样成立。本轮面向 Apple Silicon Mac 和 x86_64 Linux，Arch + niri 是用户实际环境。下列是待开发和验证的要求，既有版本的交付记录不能替代本轮验收。

### 1. 配置文件与换机

- 两端共享导入导出规则。新导出从已连接空间取得 Access Key ID、R2 地址、Bucket、空间标识，以及现行恢复文件要求的恢复信息。导入后显示已填字段，ID 可核对和修改。数据目录、应用程序和项目路径由目标电脑独立检测。
- 普通恢复文件不携带 R2 Secret Access Key。保留现有恢复密钥语义，导出前明确告知文件含同步空间恢复密钥，须妥善保管。恢复密钥与 R2 凭据在界面中分别说明用途。用户明确选择只自动填 ID，本轮不增加携带 Secret 的加密迁移包。
- 文件已载入、已连接空间、已在本机安全保存是三个可独立验证的结果。若只缺 Secret，只显示这一个必填项。切换文件或修改凭据时不混用旧空间的权限或密钥；恢复密钥与对应空间成对使用。
- 旧文件无 ID 时，只能使用本机能确认匹配同一连接的已知 ID，否则提供「从已连接的电脑重新导出」和手动输入。来源电脑本身无法读取 ID 时明确说明，不生成貌似完整的文件。旧版本升级后应能从仍可读取的既有连接重新导出，无需重新查 Cloudflare。

### 2. 系统密码库与授权

- 启动时需要恢复已保存连接、或首次需要保存凭据时，向本机安全存储服务请求访问。已经授权则直接继续；需要用户交互时由系统显示授权窗口，Sesshuttle 不收集系统密码。按服务能力检测，覆盖不同 Linux 桌面与窗口管理器，不依赖环境名称猜测是否锁定。
- 请求期间显示「等待系统授权」。用户阅读弹窗或输入密码期间，不沿用现有备用路径的 15 秒强制中止。同一请求不重复弹窗，取消后允许原地重试。
- 已连接但未能保存时保留当前连接，显示「已连接，可以同步」和「凭据仅本次有效」，提供「记住连接」。启动恢复被取消时显示「尚未连接」及「解锁并连接」。实际保存成功才承诺下次可用。
- 区分服务缺失、已锁定、取消授权、保存失败和未知原因。确实没有可用系统服务时提供针对当前环境的设置步骤、重新检查及仅本次使用；不降级为明文存储。用户修复环境后可在原任务重试，不必重新加入空间。

### 3. 浏览对话与同步范围

- 以正确标题及来源项目展示主对话，后台子会话、来源入口、占用空间和本机/云端版本状态分别可辨。同名项目或归属证据不足时标明不确定，允许用户选择。
- 「云端备份已移除，本机仍保留」归入「仅本机存在」；删除经过放在详情和记录。「使用中」独立标记，可与仅本机、已同步等状态同时出现。删除后刷新不会重新上传。
- 单条或多选后直接显示适用的上传、导入、删除操作。多选明确显示数量、筛选外的选择、附带的后台子会话和目标入口。可一次选择 Desktop、CLI、VS Code 中的多个目标。刷新本地索引、查看预览均不执行传输。
- 确认前逐条列出范围、方向、所需历史、可选附件、逻辑大小、预计新增云端用量及本次上限。大文件须明确确认，超限可调整选择。版本分歧或范围变化后重新预览，不自动覆盖。

### 4. Linux 路径、项目绑定与续聊

- 分别识别桌面启动程序、Codex 可执行文件、Codex 数据目录和项目工作目录。覆盖用户实际启动器 /usr/lib/chatgpt/ChatGPT、自定义路径、多个安装及尚无对话的项目。找到启动程序后，仍需独立验证其余路径。
- 导入现场显示当前值与检测建议，解释每个缺项的用途；支持一次保存选中的建议并返回原任务。替换有效手动路径需要明确选择。目标机项目为空或从未创建本地对话时，也能选择工作目录或明确创建专用目录。
- 分别报告历史已写入、目标入口已验证、原生项目绑定情况与能否直接打开。不支持验证时说明限制。保留原始历史，由用户自行告诉 Codex 已换电脑、现在使用哪个项目文件夹。
- 可确认普通图片缺失且必要文字和历史完整时，列出受影响图片，允许用户确认省略后继续；保留缺图说明。缺必要父历史、归属不明或安全验证失败时按具体原因处理，提供重新检查、重新指定文件或调整范围。

### 5. 结果、删除与全界面文案

- 重要操作就地立即反馈，运行中跨页可见；显示当前条目、步骤和可确定的进度。结束时分别说明云端传输和每个入口结果。下载成功但导入失败时保留下载结果，可直接修复该入口。各入口状态独立计数，避免用「已下载」代表「已导入」。
- 对预期成功、警告、部分成功、失败、中断和取消，首屏交代结果、已知原因、可执行下一步。路径、清单和诊断信息可展开。灰色主按钮旁指出当前解除条件；修复后保留选择。中英文均须核对真实界面，状态不只靠颜色或短暂提示。
- 保留本机/当前 R2/两处 × 回收站/永久删除六种组合。预览列出会处理及保留的对话、附件、版本、副本和对其他设备的影响；绝不传播本机删除指令。修改版本选择后自动重算，计算期间禁用确认，最终按钮写出位置与方式。
- 沿用 Tokyo Night Moon、内置字体和主题化菜单。检查首次配置、空列表、筛选、设置保存、导入、同步、删除、回收和恢复的实际入口及弹窗。每处重要操作都应能从所在页面完成或返回继续。

### 6. 验收与交付

1. 新旧恢复文件、缺 ID、切换空间、两端重新导出、重启后读取凭据分别验证。Mac 到 Linux 与 Linux 到 Mac 各完成一次从配置导入到目标入口继续对话的流程。
2. 用真实图形会话验证 Mac 和 Linux 的授权、取消、重试、延迟输入和重启。Linux 优先覆盖 Arch + niri；记录实际验证的密码库服务与环境。明确区分真实弹窗、模拟测试和仍待用户设备确认的行为。
3. 用隔离历史和测试对象存储验证大文件、缺图、缺关键历史、空项目、混合多选、多入口部分成功、网络中断及六种删除组合。校验重试只处理未完成项。保护原始历史，不访问真实 R2 进行测试。
4. 开发获确认后分阶段本地提交，每次带指定 Co-authored-by；不 push、不合并、不部署。完成后集中提供 Mac 与 Linux 安装包、已测范围和简短验收步骤。需求审阅期间不修改程序。

### 7. 已确认的交互与验收示例

1. 「在这台电脑记住连接」默认勾选。先验证 R2，成功后才请求系统授权。取消勾选只在内存中使用。启动时按需恢复此前保存的连接。
2. 批量操作允许显式选择可用子集。若选了 5 个，其中 1 个缺关键历史，预览显示受阻条目及原因，最终按钮写明「仅上传可用的 4 个」。执行记录保留被排除的条目及原因；导入同理。
3. 列出每张可安全省略的图片并保留逐张定位入口。可一次接受当前对话的全部缺图。确认绑定到具体清单与版本，不跨对话，不豁免必要历史、未知文件或安全检查。

### 冲突目录中的换机续聊

使用者在 Mac 上传所选对话，在 Linux 选择目标应用并继续，再传回新增历史。两台设备可以已有其他同名对话、归档、压缩文件或内部 ID 冲突。每次写入均需用户确认。界面区分传到云端、仅下载文件、导入原生应用以及原生验证。列出操作范围、未完成的步骤和可执行的下一步。不得依靠手删文件或清空目录排除已识别的无关冲突。涉及不可确定的共享记录时，应在写入前停止并展示对应位置。

### 名单外 Codex 的本机快速验证

路径有效且内核尚未验证时，导入窗口保留已选对话、入口、项目与目录，直接提供「快速验证此内核」。检测路径只处理路径问题。已有配置无需保存即可返回导入。用户主动验证时仅使用临时历史、测试消息与本机应答服务。无需登录、调用付费模型、访问 R2、关闭日常 Codex 或发送真实对话。

通过条件为目标内核能打开导入的合成历史，在同一 ID 下读回原消息并保存新一轮。可忽略额外日志、可选字段与非必要功能告警。原生项目归属单独报告，基础续聊通过即可选择「仅导入历史」。取消、超时、权限和执行环境问题显示「未完成」及对应操作。必要历史丢失、ID 改变等证据才阻止该入口的写入。其他入口、上传、下载副本、浏览和删除保持独立。

一次通过后在本机重启仍可复用。替换内核、平台或验证规则改变时重新验证。平时只检查身份，不在后台跑测试。运行时明确显示阶段、可取消，结束后在原窗口继续。一般机器目标约十秒，用有界等待适应较慢电脑。最终写入仍执行逐对话的安全检查与原生核验。

若内核要求沿用原对话的模型服务，且能明确查到目标机缺少该服务，在替换所选历史前提示服务名。补齐 Codex 配置后可重试原任务。一次验证通过的内核继续供其他对话使用。
