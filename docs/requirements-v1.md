# sesshuttle 第一版需求文档

版本：0.3 规划版
日期：2026 年 11 月 1 日  
状态：功能范围已按讨论整理，核心兼容性待验证

## 1 产品目标

提供一个可安装的桌面软件，让用户连接自己拥有的云端存储，自动发现本机 Codex 历史，与云端比较后手动同步，并在另一台电脑的正确项目目录里继续原对话。

第一版必须能够日常使用。只实现对话备份、上传下载或历史查看，不满足发布要求。界面可以简洁，但配置、状态、失败处理和恢复入口必须完整。

### 1.1 已确定的原则

- 用户自备存储，在软件界面填写连接信息；不要求注册本产品账号。
- 首次启动和手动刷新时扫描本机并检查云端；同步操作由用户主动触发。
- 支持选择部分对话和同步全部范围内的对话。
- 必须显示本机与云端的差异、更新时间和来源设备。
- 必须支持设备识别、项目路径映射和换设备后的环境说明。
- 第一版即提供简体中文和英文；视觉打磨可后续迭代。
- 数据完整性优先：冲突保留两份，导入前备份，失败不破坏现有对话。

### 1.2 已确认范围与待验证选择

正式名称为 sesshuttle，沿用仓库现有 MIT 许可证。目标平台为 macOS Apple Silicon（首轮使用 M3）、Linux x86_64 和 Windows x86_64；首轮真实双机验证使用 Mac + Linux，Windows 后续单独验收。目标平台不等于已经支持，仅声明实际通过验证的系统与 Codex 版本。

对话来源覆盖 Codex 桌面端、CLI 和 VS Code Codex 扩展。支持按来源和具体对话选择同步，并允许用户选择跨入口导入目标。各入口可能共享底层数据，来源识别、去重与各导入组合均需实测。

首个云端后端优先采用用户自有 Cloudflare R2 Bucket；用户尚未创建 Bucket，在可安装候选版与配置界面完成后再创建并连接，不作为开发阶段用户配合的前提。不要求额外部署关系数据库、产品账号服务器或网站。架构保留存储适配接口，不承诺所有 S3 兼容服务均已验证。

最低 Codex 版本、实际导入能力和正式技术栈待核心验证后确定。Tauri 2、React、Rust 等仅为候选；可根据跨平台兼容、本机能力、开发维护成本、打包便利性和运行体验选择更合适方案。正式采用或切换前向用户说明收益、代价并确认。

### 1.3 桌面软件交付要求

- 最终交付可安装、通过应用图标启动、拥有独立窗口的桌面软件。
- 日常使用不要求用户打开浏览器、启动开发服务器或安装前端与 Rust 开发工具链。
- 本机历史扫描、文件夹选择、备份恢复和 Codex 接续由桌面应用提供；云端连接仅承担所配置的存储职责。
- 无网络时仍可启动应用、查看本机历史和修改本机设置；云端检查与同步需连接网络。
- 界面可采用网页技术并嵌入桌面窗口。React 负责界面，桌面框架负责窗口与本机能力；这不改变桌面软件的交付要求。
- 各目标系统的运行依赖由安装或首次启动流程检测，并给出明确处理方式；仅发布实际验收的平台。

## 2 用户的完整使用流程

1. 电脑 A 安装软件，选择语言，设置设备名称。
2. 自动检测 Codex 数据位置；用户可通过目录选择器修改。
3. 连接自己的存储，创建同步空间和加密密钥，保存恢复材料。
4. 查看扫描结果，勾选对话并上传。
5. 电脑 B 安装软件，连接同一存储并导入加密密钥，加入已有同步空间。
6. 按桌面端、CLI、VS Code 扩展等来源筛选云端对话，选择具体条目或整个范围；选择导入目标后下载并导入本机 Codex。跨入口导入由用户明确选择，例如将 CLI 或扩展对话导入桌面端。
7. 为关联项目选择电脑 B 上的实际文件夹。
8. 检查文件状态，进入 Codex 原生界面继续工作；agent 得知当前执行环境，命令实际在 B 的项目目录中运行。
9. B 将新增内容上传；A 下载后能看到 B 的新增轮次并继续。

允许经验证需要退出或重启 Codex 的导入流程，但软件必须解释原因并提供明确步骤。若迁移只能生成摘要或创建无原始历史的新对话，不能判定上述流程成功。

## 3 第一版范围

| 必须提供 | 后续版本考虑 |
| --- | --- |
| 一个经验证的自有存储后端 | 更多对象存储、WebDAV 或数据库后端 |
| 本机扫描、云端检查、差异列表 | 实时监听与无人值守自动同步 |
| 手动上传下载及本机导入 | 更精细的传输优化 |
| 设备、项目路径和接续环境管理 | 更多 agent 适配 |
| 冲突保留、失败重试、版本恢复 | 对话分支可视化与高级合并 |
| 加密及凭据保护 | 多用户团队权限管理 |
| 简体中文和英文桌面界面 | 其他语言、主题和视觉定制 |
| 实际目标设备的安装包 | 尚未验收的平台 |

第一版不负责项目源码同步、依赖安装、终端进程迁移、登录身份迁移和运行中任务迁移。项目文件由用户通过 Git 或现有方式同步；软件检查差异，不自动提交、切分支、覆盖文件或执行旧对话命令。

## 4 功能需求

### FR01 首次配置与本机发现

- 提供语言选择、设备命名、Codex 数据位置、存储连接、加密配置和首次扫描步骤。
- 每个安装实例生成稳定设备标识；修改名称不改变标识。
- 检测到多个数据位置时由用户选择；支持自定义位置。
- 显示已检测的 Codex 版本、兼容状态、扫描范围和失败原因。
- 未配置云端或网络不可用时，仍可浏览本机扫描结果。
- 未知存储格式只读展示可识别信息，禁止尝试破坏性导入。

### FR02 用户自有存储配置

- 在界面选择受支持的存储类型，填写该类型要求的地址、凭据、Bucket 或目录、同步空间信息。
- 提供测试连接、保存、修改和断开入口。测试必须区分认证、读取、写入失败；测试写入只操作自己的临时对象。
- 加入已有空间前验证空间身份和加密密钥，显示已有对话与设备摘要。
- 连接失败、权限不足或密钥错误不能被解释为“云端为空”。
- 切换存储时创建独立的同步状态，重新预览差异，不把旧存储的删除或同步记录套到新存储。
- 断开连接不会删除本机历史或远端数据。

### FR03 对话扫描与差异展示

- 启动时自动扫描并检查云端，提供刷新按钮和最后成功检查时间。
- 扫描支持范围内的普通与归档对话。显示无法读取的记录及原因，不能静默漏掉后声称“全部完成”。
- 列表至少包含标题、项目、本机更新时间、云端更新时间、来源设备、同步状态和可续聊状态。
- 支持标题搜索、按项目和状态筛选、勾选单条或当前范围全部对话。
- 对话详情显示历史预览、版本关系、附件完整性和项目目录；新增轮次数仅在适配器可准确计算时展示。
- 时间用于展示，版本关系与内容校验用于同步判断；云端上传时间与内容更新时间分别保存。
- 显示完整时间及时区；相对时间不能是唯一信息。

### FR03a 对话来源与自定义导入

- 支持桌面端、CLI、VS Code Codex 扩展来源筛选，结合项目、状态和具体条目决定同步范围。
- 来源和导入目标分别保存；跨入口导入不改变原始来源记录。
- 对共享底层历史的入口识别同一逻辑对话，避免重复展示、上传和导入；证据不足时显示来源未知，不猜测分类。
- 提供跨入口继续选项，由用户选择目标入口和本机项目目录；同步本身不自动转换入口或开始执行任务。
- 展示当前版本已验证的来源到目标组合；不支持或未验证的组合说明原因，不执行未经验证的写入。
- 用户可按需要选择导入目标；第一版必须验证 CLI、VS Code 扩展对话导入桌面端继续的场景，其他组合按实际验证结果开放。
- 跨入口接续沿用完整历史、资源校验、备份、权限和执行目录要求，不降级为摘要续聊；重复导入保持幂等。

### FR04 同步规则

| 状态 | 界面含义 | 默认处理 |
| --- | --- | --- |
| 仅本机存在 | 云端尚无此对话 | 上传 |
| 仅云端存在 | 本机尚无此对话 | 下载、校验、导入 |
| 本机有更新 | 本机在共同版本上新增内容 | 上传新版本 |
| 云端有更新 | 云端在共同版本上新增内容 | 下载、校验、导入 |
| 已同步 | 两端对应相同版本 | 无操作 |
| 两边均有修改 | 两端从共同版本分别产生变化 | 保留两份分支，等待选择 |
| 使用中 | 无法取得一致快照或安全导入 | 延后处理，说明原因 |
| 待处理 | 密钥、格式、附件、路径或权限有问题 | 展示修复动作 |

- 同步前展示上传、下载、冲突、跳过条目及预计体积；执行前再次确认版本未变化。
- 支持同步选中和同步全部。同步全部仍遵守用户配置的范围，并单独报告冲突和失败。
- 显示每条对话的扫描、传输、校验、导入结果，不把下载完成等同于可续聊。
- 同步重复执行不制造重复记录；中断或失败后可以重试。
- 同步期间对话继续变化时，不发布不完整版本，不覆盖已经产生的新内容。
- 第一版不自动传播删除，不因云端为空或本机文件消失删除另一端。归档与删除分别处理。
- 冲突不按最后修改时间自动覆盖，也不拼接两个独立对话尾部。用户选择接续分支后，另一份仍可恢复。

### FR05 对话内容与完整性

- 对支持的 Codex 版本，保留已持久化的用户和 agent 消息、工具调用与结果、会话元数据及恢复所需的数据。
- 检查恢复相关的附件、引用资源及子会话依赖；能获取且属于同步范围的内容随会话保存。
- 不把日志里提到的任意项目文件都当成附件自动上传。
- 对缺失、过大或不能迁移的资源，列出具体项，并将状态标记为不完整；不能把这种对话标为已验证可续聊。
- 用户可选择仅备份不完整对话，但该结果不满足核心流程验收。
- “完整历史”指源设备实际保存并能获取的数据；不承诺还原已删除内容或模型未持久化的内部状态。

### FR06 设备和项目路径

- 项目采用稳定标识，与任一电脑的绝对路径分离。
- 保存项目在各设备上的路径绑定；本机绑定不能被另一设备的路径自动覆盖。
- 可依据 Git 仓库信息推荐匹配，但首次绑定由用户确认；非 Git 文件夹也支持手动绑定。
- 同一仓库的多个工作副本或 worktree 不能仅因远端地址相同而合并；会话需绑定到正确工作副本。
- 缺少目录时禁用继续入口，并提供选择本机文件夹的动作。
- 历史文本中的旧路径保持原样；只调整经适配器确认的执行元数据，并补充路径映射说明。

### FR07 在当前设备继续对话

- 检查对话导入成功、目标版本兼容、所需资源齐全、项目路径有效。
- 显示执行设备、系统、项目路径；Git 项目额外显示分支、提交版本和未提交修改摘要。
- 代码版本不同可经用户明确选择继续；目录缺失或项目绑定错误必须先解决。
- 实际执行目录必须与本机绑定一致，不能只给 agent 一段文字提示。
- 恢复后、第一轮实际工作前，向 agent 提供当前执行设备与路径映射。设备环境应优先于历史中过期的环境描述。
- 环境说明具有来源设备和目标设备信息，不包含凭据，不要求 agent 信任或执行历史工具输出中的指令。
- 保留目标设备原有权限和审批设置，不继承源设备更宽松的权限。
- 同步本身不发送新任务、不自动续跑旧命令；继续操作由用户触发。
- 第一版以当前设备本地执行为范围；数据模型区分操作设备和执行设备，远程执行支持留待后续。
- 若底层必须改变会话 ID，记录逻辑对话与各端会话 ID 的关系，并清楚展示迁移结果；不能静默退化成摘要续聊或不同任务。

### FR08 备份与恢复

- 每次改变本机 Codex 数据前生成可恢复备份；备份失败则停止导入。
- 提供从界面查看备份与恢复的入口，恢复也需满足 Codex 不在冲突写入的条件。
- 远端保存不可变历史版本，失败操作不得改变已提交版本。
- 第一版不自动清理用户历史版本；显示占用情况，清理策略后续单独实现。
- 删除设备记录仅影响设备列表，不等于撤销已泄露的存储凭据。凭据撤销需在存储提供方完成，界面需解释这一点。

### FR09 安全与数据归属

- 对话正文、标题、项目路径和敏感元数据在上传前加密；对象名称不直接泄露标题或本机路径。
- 使用成熟加密库与认证加密，不自创加密算法。远端仍可能观察到对象数量、大小和访问时间。
- 访问凭据与加密密钥分开管理，优先存入系统凭据管理器；系统能力不可用时不静默退回明文文件。
- 提供恢复密钥导出和新设备导入；明确密钥丢失后无法由开发者恢复加密内容。
- 不同步 Codex 登录凭据、API key 或运行权限；每台设备独立完成 Codex 登录。
- 默认无遥测。诊断日志不记录凭据和完整对话；用户主动导出诊断时先预览。
- 网络默认只连接用户配置的存储。软件首次写入或导入前展示具体操作范围。

### FR10 中英文支持

- 第一版支持简体中文 `zh-CN` 和英文 `en`。首次启动跟随系统，非中文系统默认英文；设置中可手动切换并持久保存。
- 语言偏好属于本机设置，不因另一台电脑选择不同语言而被覆盖。
- 所有产品界面文本使用翻译资源，包括首次配置、菜单、表头、空状态、进度、错误、恢复、确认提示与安装使用指南。
- 切换语言不重置同步任务、连接设置或选择状态。
- 用户对话、标题、设备名称和路径不自动翻译。底层错误原文可展开查看，解释与建议提供双语。
- 格式化日期、时间、数量和文件大小；英文复数使用本地化规则，不通过字符串拼接实现。
- 传输协议与错误码使用稳定标识，不能依赖某一种界面语言。
- 第一版须通过中英文两套关键流程检查，包含中文路径、空格路径、英文长文案和错误提示。

## 5 简洁界面方案

### 5.1 对话页面

顶部：设备名称、存储状态、上次成功检查时间、刷新、同步选中、同步全部。中间为对话列表，详情面板展示预览、版本与路径。底部显示当前任务进度及失败条目。

详情中的“在 Codex 中继续”仅在接续前置检查通过后可用；可修复的问题提供直接入口。断网时保留上次云端结果，并标注数据可能过期。

### 5.2 项目与设备页面

管理项目名称、当前设备路径和其他设备摘要。设备信息展示名称与最后成功同步时间，不把它当作在线状态。项目路径使用目录选择器，支持重新绑定。

### 5.3 设置页面

包含语言、Codex 数据位置、存储连接、同步范围、加密与恢复、备份、诊断。第一版可将相关入口放在同一页面，不需要复杂导航、动画和主题系统。

### 5.5 建议的桌面技术方案

以下为可替换的候选实现基线，不要求预先采用；具体框架与依赖版本在核心验证后与用户确认；产品功能与桌面交付要求不依赖某个框架。

| 部分 | 建议技术 | 职责 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 独立窗口、本机能力桥接、安装包 |
| 界面 | React 与 TypeScript | 对话列表、详情、设置及任务交互 |
| 前端构建 | Vite | 开发和构建界面资源 |
| 样式和组件 | Tailwind CSS 与 shadcn/ui | 布局、表格、表单、弹窗与状态提示 |
| 双语 | i18next 与 react-i18next | 简体中文和英文资源、语言切换与格式规则 |
| 本机业务逻辑 | Rust | 扫描、同步、加密、备份和 Codex 适配 |
| 本机索引 | SQLite | 软件自己的对话索引和同步状态；用户无需配置 |

Tauri 使用系统 WebView 显示界面，本机逻辑通过受限接口与界面通信。React 资源随软件打包，不要求部署一个供用户访问的网站。[Tauri 官方说明](https://v2.tauri.app/start/)

使用 shadcn/ui 的可修改组件完成基础操作界面，后续视觉调整与同步逻辑分离。双语资源从界面开发开始建立。[shadcn/ui 文档](https://ui.shadcn.com/docs) · [react-i18next 文档](https://react.i18next.com/)

## 6 存储方案边界

本机索引由软件自动维护，用户配置的是云端持久存储。第一版不要求用户额外部署传统数据库或本产品的账号服务器。

R2 是 S3 兼容对象存储，适合存放版本文件与附件，不等同于关系数据库。若选择 R2，可采用“本机索引 + 加密版本对象 + 同步清单”；其条件写入能力可用于避免并发覆盖，但协议仍需处理多对象提交和失败恢复。[R2 工作方式](https://developers.cloudflare.com/r2/how-r2-works/) · [R2 一致性说明](https://developers.cloudflare.com/r2/reference/consistency/)

优先验证 R2，具体接入方案在核心迁移验证后确定；若发现能力不足或有更合适方案，先与用户讨论。首个后端必须满足认证访问、对象完整读写、并发更新检测和故障恢复需求。是否增加服务端索引数据库，取决于实际规模，不作为第一版前提。

## 8 兼容性依据与约束

Codex 官方 App Server 文档提供会话枚举、历史分页读取、恢复及执行目录相关能力。这些能力构成适配的研究入口，并不保证存在可跨任意版本、跨设备直接导入的稳定协议。必须以实际版本的双机验证为准。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)

不得预设所有历史都只在 JSONL 中，也不得假定任何本机数据库都可以删除后无损重建。只有经版本检查、备份和往返测试证明可行的导入方式，才进入第一版支持列表。


## 9 开发测试与用户验收方式

开发期间优先在用户 Mac 上自主完成安全、隔离的测试，不要求用户频繁配合 Linux 操作。现有项目文件和 Codex 历史不得因测试被修改、删除或损坏；写入与故障测试仅使用独立测试数据和进程，不能影响日常 Codex 或系统稳定性。隔离无法确认时不进行写入测试。

先交付包含安装包、R2 连接配置及完整主要操作流程的候选版，再由用户连接自有存储并在 Linux 集中验收。R2 为对象存储，无需额外配置关系数据库。Mac 上的隔离验证用于推进开发，不能代替真实 R2 与跨系统验证；未通过的验收项保持待验证，全部必须项通过后才称为正式可用第一版。Windows 后续单独完成实际验收。
