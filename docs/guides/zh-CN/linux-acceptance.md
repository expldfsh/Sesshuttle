# 在 Arch 上验收已有的云端对话

适用于已经把 Mac 对话上传、并能在 Linux 看到该标题的用户。两台电脑更新到 Sesshuttle **0.5.0**，保留原同步空间、应用数据和恢复文件。[安装和连接步骤](quick-start.md)

1. **检测桌面程序。** 在 Linux 打开 GPT 桌面端的 Codex 页面。打开 Sesshuttle 的「本机应用与项目 → 检测本机 Codex 环境」。核对「GPT 桌面端」下的内核、历史目录和检测依据，再点「应用所选配置」。也可在导入时完成这一步。`/usr/lib/chatgpt/ChatGPT` 是已知的一种桌面主程序位置。
2. **选择对话。** 在 Sesshuttle 的「对话」页，点你已上传的标题 →「导入到这台电脑…」。看不到时点「设置 → 查看云端对话」并刷新。选择目标「GPT 桌面端」。
3. **选中真正的项目。** 在「导入到本机项目」选 Linux 侧栏里那个 `linux`。里面没有任何本地对话也可以选。工作目录可选已有文件夹，或点「创建并使用专用工作目录」。如果只看到「仅导入本机历史」而需要项目归属，先核对所选内核版本和实际历史目录。
4. **执行。** 点「查看本次清单」，核对标题、目标项目和应用。退出正在使用历史的 Codex 后，点击确认导入。若只有截图缺失，可重新指定该图，或在当前对话内逐张确认、一次接受所有可省略的图片。
5. **在 GPT 验收。** 等待结果显示目标已验证及所选项目名称。点「继续」，或从 Linux 自己的 GPT 桌面端打开 `linux` 项目下相同标题。确认早期消息、工具记录和预期图片都能看到。若省略过图片，检查对应位置的缺图说明。
6. **亲自交接。** 例如告诉 Codex“现在换到我的 Linux 电脑了，工作目录是……”，请它说出一条早期对话里约定的内容并检查当前工作目录。确认这条新消息和回复能在同一条对话中保留。
7. **反向验证。** 结束对话并刷新 Linux 端，点标题 →「上传到云端…」。在 Mac 刷新同一标题 →「导入到这台电脑…」，核对目标后确认。打开原生入口，应看到 Linux 的新轮次并能接着聊。

**怎样判断结果**　「已加入同步空间」说明可以访问自己的备份。「已同步」说明该版本与云端一致。导入结果分别列出应用与项目验证。最终用你安装的 GPT 客户端打开同一标题、看见旧消息并发出新一轮，就是这台电脑的验收结果。

若遇到阻断，优先使用当前提示旁的修复或重检按钮。反馈时提供 Sesshuttle 版本、目标应用、错误码、发生在哪一步即可。有关凭据、附件或恢复的操作见[故障对照表](quick-start.md#遇到提示后如何继续)。

## 验收换机配置与授权

如果已经连好，两端直接使用原来的空间。要核对换机配置，可先用新版在已连接的 Mac 导出恢复文件，在另一台尚未连接的 Linux 安装中导入。看到 Access Key ID 已填好后，输入 Secret Access Key 并连接。「已加入同步空间」说明可以使用。密码库已解锁时可能直接保存，锁定时在系统窗口授权。选择取消时可以继续本次同步，随后在「设置 → 记住连接…」重试。保存成功后重开应用，核对同一空间和云端对话可见。反向导入 Linux 导出的文件时步骤相同。

## 验收删除

1. 在两台设备用一条专门的测试对话。先在 Mac 上传两个版本并将一个版本导入 Linux。
2. 在 Mac 的删除清单中选「仅云端 → 移入回收站」，核对或调整版本范围。Linux 刷新后，已导入的本机对话仍可打开。在 Linux 的「备份与恢复 → 云端回收站」可查看并恢复刚回收的版本。
3. 用「仅本机 → 移入回收站」检查本机与云端的独立性。云端标题和 Linux 原有历史仍在。回到 Mac 的本机回收站可以恢复。
4. 要检查永久删除界面，选择「本机和云端 → 彻底删除」，先看两侧清单及保留副本，核对末步按钮。取消即可验收预览。开发阶段已对全部六种组合执行实际的隔离删除。

## 已经看到扫描提示时

展开「查看扫描时遇到的问题」。如果列出的内部 ID 冲突属于别的对话，可以直接选中要导入的标题。若正好是要处理的那一条，点「比较本机历史副本」，核对路径、大小和最近消息。「只上传这一份」保留本机各份原件；「在 Codex 中使用这一份」会按确认清单把其他副本移出 Codex 的活动目录。确认框会列出路径。涉及本机数据库关联时，按显示的关联路径选择。只想把云端内容取回磁盘，可在对话详情的「云端历史版本」选择「仅下载云端副本到文件夹」。
