# Mac + Linux 集中验收

这份清单用于拿到候选包后一次性验证真实 R2 和 Linux。开发者已经完成的测试见[候选版验证记录](../../validation/rc4-candidate.md)，下列实机项目尚未代用户勾选。

## 准备

- 一台 Mac Apple Silicon 和一台 Linux x86_64，有各自的 Codex 登录与项目工作副本。
- 安装 sesshuttle 候选版，按[配置指南](quick-start.md)在 Mac 创建空间、Linux 加入同一空间。
- 首次只用一个专用验收项目和几条测试对话。两台电脑项目路径应不同，至少一个路径含空格或中文。
- 记录系统版本、Desktop/CLI/VS Code 的 Codex 版本。当前目标运行时范围为 `0.166.0`、`0.164.0`、`0.164.0-alpha.11.1`、`0.166.0-alpha.5.1`；未知版本会停止导入，不需要降级或删除原历史。

## rc.4 先在 Mac 检查

- 升级后继续使用已有 R2 连接，不重新创建空间。
- 核对原生对话标题、主/后台分类；压缩历史应可见，不提示为丢失。
- 用“自动检测”查看路径；不点击“使用此路径”时，原配置应保持不变。
- 查看每条对话大小和预览总量。把上传上限调低，应阻止超过上限的计划；不要以实际耗尽空间验证。
- 首次选择小的测试对话，不全选全部真实历史；默认使用“上传备份”。预览必须列出每个实际包含的会话和原因，后台子会话默认不加入。
- 外部截图显示“文件存在，等待授权包含”时，逐项勾选并“更新预览”；核对体积后点击“确认并上传所列对话”。此时只上传，不向本机 Desktop 导入。
- 原生项目名称应与桌面项目对应；存在歧义时明确显示，手动绑定的是当前设备的代码目录。
- 用专门的测试对话验证“删除本机对话”及回收站恢复；不要用日常重要历史做首次删除测试。共用附件、代码文件、云端副本必须仍在。

## 验收顺序

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 1 | 在两台电脑通过安装后的图标启动软件，切换中英文 | 无开发工具或字体安装要求；离线文字清晰；菜单与主题一致，鼠标/键盘均可操作；语言切换保留选择 |
| 2 | Mac 的 Desktop、CLI、VS Code 分别建立测试对话 | 来源分类正确；共享目录不重复；无法判定的记录明确标未知 |
| 3 | 一条对话的第一轮设置随机标记，再加几轮中文/英文、一次低影响工具调用、一个小图片 | 历史预览包含正确内容；结束当前轮次 |
| 4 | Mac 选择该对话并“上传备份” | 已备份；R2 对象中无法直接读出标题、路径或正文 |
| 5 | Linux 加入空间并刷新 | 能看到来源、云端版本和来源设备；本机尚未导入 |
| 6 | 在 Linux 绑定正确项目，选择已安装入口并退出 Codex，执行下载导入 | 自动备份；每个目标有独立状态；共享历史只出现一次 |
| 7 | 在 Linux 原生 Codex 打开导入对话 | 原消息、工具结果、图片与归档状态正确；不是摘要新建对话 |
| 8 | 在原生 Codex 中要求回忆早期标记，执行 `pwd` 并读取只存在于 Linux 工作副本中的测试文件 | 早期上下文仍在；实际命令目录与文件属于 Linux 项目，而非源电脑路径 |
| 9 | Linux 续写一轮并上传，Mac 退出 Codex 后下载并继续 | Mac 能看到 Linux 新内容，且在 Mac 的绑定路径执行；原消息不重复 |
| 10 | 重复同一个版本的导入；再测试 IDE → 全部适用目标、Desktop → IDE + Desktop | 无重复对话或消息；每个入口结果正确；未安装目标单独报告 |
| 11 | 在两个设备离线分别续写，再依次上传 | 显示分歧，保留两份；可明确选择版本；不按时间自动覆盖 |
| 12 | 暂时断开存储连接或使用错误密钥加入，再恢复正确连接 | 错误可见；不把云端失败当成空空间；本机数据不变 |
| 13 | 选一个测试导入备份执行恢复，再在原生 Codex 检查 | 原历史可读且可继续；恢复前状态仍有安全副本 |
| 14 | 一个目标故意留空，再只修复并重试它 | 显示部分完成；其他成功目标保持记录；定向重试可用 |
| 15 | 用专用测试对话验证本机删除、依赖清单和回收站恢复 | 删除后本机列表移除；云端保留；恢复后可查看历史，其他对话未改变 |
| 16 | 重启 sesshuttle，确认凭据保护和恢复文件在 Linux 上工作 | 能重新连接；若系统密钥环不可用，应明确提示仅内存保存 |

不要求耗尽磁盘、强制终止日常 Codex 或删除数据库来测试故障。开发阶段已对合成数据做过中断、损坏包和并发检查。

## 反馈格式

记录：步骤号、系统/架构、Codex 入口和版本、预期与实际结果、错误码。可使用“设置 → 诊断预览”，分享前确认内容。不要发送 R2 Secret Access Key、恢复文件或真实对话正文。

全部实际通过后再签核 AC01–AC15；本清单本身不代表已通过。

## 这次第一次安装 Linux 的简短路线

1. 先在 Mac 安装 rc.4，保留已有应用数据、R2 连接和恢复文件，不创建新空间。
2. 选择一个已结束的小测试对话，保留默认“上传备份”，处理预览里的具体附件授权，再确认上传。
3. Linux 安装 rc.4，配置同一个 Bucket 并导入 Mac 的恢复文件，选择“加入已有空间”。
4. 刷新后勾选该云端对话，在“项目与入口”绑定 Linux 的项目工作副本，检测并配置已安装的 CLI / VS Code 等入口。没有安装的入口不勾选。
5. 退出占用目标历史的 Codex，方向改为“下载导入”，勾选需要的本机入口。预览应显示 Linux 的数据目录和项目目录，确认后执行。
6. 各目标显示“内核已验证”后，打开实际 Codex 入口，核对旧消息、图片、早期上下文和当前工作目录，再继续一轮。完成后 Linux 上传、Mac 下载，验证反向接续。

如果任何一步失败，保留错误码和对应版本，停止该条导入。不要删数据库、不要重新创建空间、不要靠允许不完整备份绕过接续错误。

## 本轮新增：缺图接续验收

只用专门的测试对话：让它包含一张临时测试图片、几轮文字及一个早期标记。结束对话后把该测试图片移到别处保留，不删除真实附件。

1. Mac 预览应逐项显示缺失图片。未勾选接受缺图时执行不可用；确认指定图片后可以上传。
2. Linux 下载导入时应再次要求逐项确认；导入成功后各目标显示“已导入 · 部分附件缺失”，继续按钮可用。
3. 原生 Codex 中旧文字和工具记录仍在，原图片位置有缺图说明。继续一轮，验证早期文字上下文和 Linux 工作目录；不要求模型恢复缺失图片细节。
4. Linux 上传、Mac 下载后，缺图说明仍保留。若缺少关键历史或父对话，应明确阻止，不能靠缺图确认放行。

以上是新增实机验收项，开发阶段已在 Mac 的隔离普通/压缩样本及本机模拟存储中通过，未代替真实 R2 与 Linux 验收。
